# 自动交易系统 Windows EXE 使用说明

版本：0.1.0.dev54。交付范围：Windows 独立 QMT 交易节点、本机操作台和隔离的模拟演示入口。

## 1. 文件和运行要求

正式调试请双击项目根目录的 `打开自动交易系统.cmd`。首次使用或原配置失效时也能进入完整操作台，页面显示“尚未连接 QMT”，所有交易功能保持锁定；在“系统设置”点击“开始连接 QMT”即可进入接入页面。只看离线演示时双击 `打开模拟演示.cmd`，也可以运行 `dist/AutoTradingSystem-0.1.0-dev54.exe --preview`。EXE 内含 Python、运行依赖和页面资源，不需要另外安装 Python 或 Node.js。目标为 Windows 10/11 x64，本次实际验收环境为 Windows 10 x64（19045）。

QMT 交易端、券商 XtQuant SDK 及 `userdata_mini` 不在此 EXE 中；正式入口会使用目标机器上已安装并明确配置的路径。量化后台仍是独立服务，不包含在本文件中。

此私有构建没有数字签名。Windows 可能显示“未知发布者”；应先核对文件来源和随附 SHA-256，不需要关闭杀毒软件。

当前成品大小：27,896,386 字节；SHA-256：`FF4E8A86294CFE5AB266C50C62A2BEE88C08E14B0DF55E8F825869F0C9F6E349`。

## 2. 双击使用

1. 正式入口首先读取已保存的 QMT 接入设置。没有可用配置时打开未连接操作台，交易能力全部锁定；从“系统设置”保存并检查通过后自动切换到实盘节点。模拟演示入口会打开“自动交易系统 · 离线模拟版”窗口。
2. 等待引擎、监护、同步代理和本机操作台启动。窗口显示当前访问地址，并自动打开默认浏览器。
3. 页面包含首页、QMT账户、尾盘策略、交易监控、消息与日志、系统设置。技术运行信息折叠在系统设置的高级区域。启动器的“打开操作台”按钮可以再次打开页面。
4. 模拟演示使用本次自动生成的 `paper-desktop-...` 模拟别名，默认 MOCK、零交易额度并保持暂停。正式入口不会使用这个模拟账户，账户号和操作员登录信息来自正式节点配置。
5. “打开本次数据目录”用于查看本次配置、状态和工作进程日志。
6. 点击“停止并退出”，或者关闭启动器窗口，会先请求暂停及正常停止，再回收本次启动的进程。关闭浏览器标签页本身不会停止节点。

端口由程序从本机可用端口中分配，访问地址以启动器显示为准；仅监听 127.0.0.1。当前账户没有发布计划时，显示“尚未加载计划”是正常状态。

## 3. 数据和进程归属

每次打开会在 `%LOCALAPPDATA%\AutoTradingSystem\DesktopPreview\session-...` 创建新的受保护目录。临时通信秘密只保存在进程环境，不写入配置或 EXE。

每次是独立预览会话，旧目录保留，没有自动删除功能。这些目录不是正式账户的跨日运行配置。关闭程序只操作自己创建的 Windows Job 和子进程，不会按名称查杀 Python、QMT 或其他量化程序。

模拟演示不会调用量化生产接口，不连接真实账户，也不会提交交易。正式入口只有在正式配置通过校验后才启动，并且每次启动仍保持暂停，必须完成操作员登录、账户恢复核对和本次授权后才能自动发单。

## 4. 当前能力

- 自带桌面启动窗口，编排现有 engine、supervisor、agent 和 console。
- 支持冻结程序内部的节点工作进程分派，包括 supervisor 创建的 engine 子进程。
- 本机操作台使用当前前端构建，额度、账户、持仓、委托、成交和运行状态均从交易节点读取。
- 正式闭环包含量化后台计划读取、QMT 行情订阅、风控买入、超时撤单、券商终态核对、剩余数量重报、逐笔成本持仓，以及次日止盈、止损和最晚卖出。
- 紧急清仓只处理本系统登记的策略持仓，会先撤销本系统未完成委托并等待券商终态，不处理手工持仓。

当前代码闭环已经完成。正式使用前仍需在目标机器写入量化后台、账户、SDK、交易日历和密钥等现场配置，并在交易时段由账户持有人明确授权一笔小额报单、撤单和回报核对；读取资金与持仓不能单独证明券商已经放开函数交易权限。

## 5. 交付验证

成品验证使用 EXE 自身的 `--self-test <全新目录>`，在包含中文和空格的路径运行；测试时移除 PYTHONPATH/PYTHONHOME，并将 PATH 限定为 Windows 系统目录。验证 Tk 加载、三组件状态、真实本机 HTTP/静态资源、MOCK/零额度及自有 Job 退出。

源码测试、构建环境、文件摘要、成品测试结果及变更范围保存在仓库验收记录和 `.codex_tmp` 构建目录中。代码与冻结程序已经达到现场 QMT 联调阶段，现场配置和小额真实委托验证尚未完成。

本次最终结果：Python 全量 2513 项通过，覆盖率 90.00%；Ruff、格式和 mypy通过。前端 lint、格式、类型、50 项测试、覆盖率和生产构建通过。量化后台自动交易模块 175 项通过，13 项因本机未启动专用测试 MySQL 而跳过。跨项目 Windows 端 163 项、量化后台端 68 项契约测试通过，48 个契约文件摘要一致。

最终 EXE 在全新目录完成自身验收：Tk 加载正常，首次设置页、操作台与 4 个静态资源可访问，engine、agent、supervisor 三个所属进程均为当前状态并在退出时回收；验收保持实盘开关关闭、订单数为 0。候选文件与 `dist/AutoTradingSystem-0.1.0-dev54.exe` 的大小和 SHA-256 完全一致。本轮没有发送真实委托。当前默认 EXE 大小为 27,896,386 字节，SHA-256 为 `FF4E8A86294CFE5AB266C50C62A2BEE88C08E14B0DF55E8F825869F0C9F6E349`。

## 6. 开发者重新构建

使用独立 Python 3.11 x64 构建环境，安装 runtime.lock 和 windows-exe.lock 中的固定依赖。先执行操作台类型检查和 Vite 构建，将输出写入新的独立目录，再执行：

```powershell
./scripts/build-windows-exe.ps1 `
  -Python <构建环境python.exe绝对路径> `
  -FrontendAssets <本次前端构建目录绝对路径> `
  -Destination <全新输出目录绝对路径>
```

构建脚本拒绝覆盖已有输出目录，工作资料保留在 `.codex_tmp/exe-build-...`。先完成源码质量门和成品验证，再复制经过摘要核对的成品到交付目录。
