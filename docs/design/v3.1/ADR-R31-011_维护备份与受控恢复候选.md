# ADR-R31-011：维护备份与受控恢复候选

日期：2026-09-26。实现：dev52。范围：R31-005/018的Windows维护备份与恢复演练。

## 1. 固定交付边界

本轮采用“暂停交易、停止引擎与监护、独占维护、恢复到新目录”的流程。交付三个命令：backup、verify-backup、restore-backup。备份包含最小Journal及同步相关文件；恢复交付带启动阻断的候选副本，供后续券商事实核验和部署代际切换。在线仅暂停的自动备份、定时清理及正式恢复激活分别实施。

本次选择停机窗口，是因为完整备份同时涉及Journal Owner、引擎文件发布者、监护状态和agent索引。通过现有账户/监护互斥锁和agent任务租约冻结写入者，形成边界清楚的第一套完整数据保全工具。维护期间定时触发的agent任务会报告占用，后续原批次续传；engine/supervisor启动竞争受到同一互斥锁约束。

## 2. 文件集合和写入方式

代码分层：节点CLI负责命令与交互确认；runtime/node_backup负责维护互斥、路径/权限、清单和恢复阻断；journal/apsw_backup负责数据库复制与核验，并将驱动错误转换为项目异常。架构测试仅允许Journal运行适配器与维护适配器引用APSW，运行编排和CLI保持驱动无关。

| 对象 | 方式 |
| --- | --- |
| `critical/journal-v2.db` | SQLite Backup API读取已提交主库和WAL，输出独立DELETE模式数据库 |
| `critical/supervision-state.json` | 有则原样保留，包含熔断/失败历史 |
| `artifacts/<hash>.json` | 保留计划原文、日终分片、回执及其他不可变业务证据 |
| `daily-catalog/<日期>[.r版本].json` | 保留全部已发布版本引用 |
| `jobs/<hash>.json`及范围/重试游标文件 | 保留任务状态和公平续传位置 |
| `manifest.json` | 最后写入，包含范围、完成时间、逐文件长度/hash和Journal核验摘要 |

配置文件、生产密钥和运行口令由原凭据体系保管；日志和Tick归档沿用各自留存体系。临时发布文件与主库WAL/SHM不作为普通文件复制，WAL已提交内容由Backup API合并到备份数据库。

目标目录须为全新、绝对、与源目录互不包含的路径，父目录已存在。产品仅给本次新建目录配置当前运行SID与SYSTEM权限。白名单约束相对路径；符号链接、重解析路径、硬链接和非普通文件被拒绝。已有目标目录原样保留。失败后保留部分目录供诊断，再次操作选用新的目标路径。

## 3. 核验与完成标准

清单包含配置scope_hash，绑定节点、账户、节点代际、配置Journal代际、MOCK模式及运行SID；数据库内部storage_generation单独记录，明确区分现有两种标识。本次沿用原代际，SQL结构保持原样。

Journal验证包括应用ID/Schema版本、精确DDL、quick_check、外键、账户、J1正文hash/身份/单调序号、动作目标的历史收紧及最终投影、回报/控制/检查点的规范化正文摘要。成功不等于券商业务账已核实；原同步任务和业务关系仍由现有恢复/续传流程及后续人工审查确认。

备份成功输出manifest_hash。校验及恢复必须提供备份时独立记录的摘要；逐文件hash用于损坏检测，不提供抵抗已获文件访问权限者的签名身份认证。备份完成后应把摘要留在独立运维记录中。

资源上限：16,000个文件、单文件512MiB、备份文件总量4GiB、清单4MiB；数据库复制60秒，J1及动作目标核验各100,000条上限。文件按1MiB块处理。达到边界时报告维护错误，保留已有证据。扩容需要容量与时间预算验收。

## 4. 恢复的安全状态

restore-backup支持原数据目录已不可用的情况；它校验选定备份、取得同账户/监护独占锁，在全新受保护目录先写restore-pending.json，再复制文件和复核数据库。完成后写node-scope.json及restore-verified.json；源目录和备份文件保持原样。

validate_layout检查restore-pending.json：引擎、agent、supervisor和现场台均拒绝把候选目录作为正常运行目录。部分恢复和完整候选副本都保留此阻断。CLI要求当前终端逐字确认`RESTORE CANDIDATE <账户别名>`。候选目录初始化采用新目录限制，也不会绕过该阻断。

正式启用候选副本需要核实备份之后的券商委托、成交、资产和量化已接收版本，处理证据缺口，再执行受审计的部署代际切换。该激活流程尚待实现及QMT现场验证；本轮命令只交付受控候选副本。保持标记原样，后续由正式激活流程接管。

## 5. 运维与后续

当前命令按需运行，Windows已注册任务保持原样。备份目标应配置在独立故障域；本轮隔离测试证明软件读写和失败行为，物理断电、整盘损坏与异机SID迁移需目标环境证据。20交易日保留和自动维护调度是后续工程项，当前保留全部备份。

回退代码时保留新目录和全部数据；候选目录只由识别恢复阻断的dev52及后续版本检查，旧版程序不能用于启动该候选目录。后续交付项包括：候选核验/代际切换、自动备份调度/留存，再继续Recorder/Replay和账单对账。真实策略和真实交易权限保持既有准入边界。
