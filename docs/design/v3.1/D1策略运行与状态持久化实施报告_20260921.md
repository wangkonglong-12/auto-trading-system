# V3.1 D1策略运行与状态持久化实施报告

日期：2026-09-21。交付版本：0.1.0.dev43。验证环境：Windows、Python 3.11.16。

## 1 本轮实现

本轮接入持续调用的D1策略owner，补齐无子单及在途委托期间的独立规则状态，并以签名开盘退出上下文驱动SELL-only会话。运行组合根固定使用Mock Broker，真实交易保持关闭。

| 已实现内容 | 行为与边界 |
| --- | --- |
| 同owner持续驱动 | 一轮依次推进engine、消费异步结果、核验恢复引用、评估规则和形成子单；SDK及Journal各自使用原工作线程 |
| 独立规则状态 | 保存目标、已触发/已检查规则及离散路径质量，即使没有订单也可恢复；行情与连续峰值计算保持内存态 |
| 在途目标收紧 | 在途委托存在时先保存更严格目标，保持原预占；原委托终态、成交及账户核对完成后计算实际剩余子单 |
| 独立开盘上下文 | Ed25519签名、账户/策略/日期/开盘摘要/日历绑定、价格与数量规则、窗口及限额；同账户同日正文固定，避免变更编号重置检查 |
| 独立退出授权 | 买入额度0、方向SELL、本次boot恢复确认和本地授权；演示启动后下午买入计划保持未加载 |
| 行情和数量保护 | 最多15标的最新值、双时钟2秒新鲜度、午休和截止过滤、倒序/未来时间暂停；数量步长及零股全量清仓由引擎再次验证 |
| 撤单与补单 | 无更新达到签名参数（样例30秒）或进入停止新增窗口时请求撤单；过期行情仍允许按已知订单事实撤单，待确认后补足目标 |
| 兼容与契约 | 旧J1默认字段省略保持摘要兼容；新增本地退出上下文、状态Schema及字段说明；SQL维持六表27字段 |

实现分布：`strategies/exit_context.py`负责本地契约和验签，`exit_state_store.py`负责有界不可变状态链，`exit_owner.py`负责持续驱动；`runtime/execution_scope.py`归一化Entry/Exit执行范围，`EngineKernel`继续持有账户、订单、授权和预占。设计决策见[ADR-R31-003](ADR-R31-003_D1持续运行与独立状态.md)。

## 2 两条已验证闭环

### 2.1 无报单状态在重启后保留

1. D0实成交100股并完成收盘封存。
2. D1使用独立退出上下文，10:30价格10.40、前收10.00，完成检查但目标仍为100股，形成一条状态、零订单。
3. 关闭并重建内核和Journal，账户重新核对，默认保持暂停且旧授权失效。
4. 新的SELL授权后，10:31价格回到10.00，保留已完成的10:30检查，目标仍为100股；订单仍为零。

### 2.2 在途收紧、撤单确认和余量清仓

1. D0封存100股；D1开盘减仓目标剩余50股，首子单提交50股。
2. 首单实成交20股，批次实际剩余80股；原单余量30股继续预占。
3. 后续行情触发清仓，先保存目标0；在途订单仍只有一笔。
4. 订单持续无更新30秒后请求撤单；此时旧行情已经过期，仍按已知原单事实撤单。
5. 原单终态和账户核对完成，收到新鲜行情后补卖80股，最终持仓0、券商订单两笔。
6. 再次重建内核，恢复状态和实际持仓一致，继续保持暂停。

这里的“重启”是同一测试进程内关闭并重建内核及存储线程，完整engine进程强杀矩阵列入后续验收。样例成交价、成本、日历和数量步长是明确Mock规则，不代表已完成目标券商资格验证。

## 3 SQLite、缓存与业务数据的具体分工

SQLite继续使用既有最小关键Journal。新状态记录写入`recovery_checkpoints`，每个上下文最多256条，带连续序号、前条摘要及账户/日期/批次绑定。恢复读取全部有界槽位，检查缺口、错归属、摘要链和目标单调性。每个新SELL在原J1中携带这条状态的摘要，恢复时检查其存在且内容匹配。

日常报价、峰值、策略计算和页面快照仍使用内存；同一离散状态不会随每个Tick重复保存。发生规则检查/目标变化时先完成一次状态提交，每个实际子单再完成原有J1。独立状态写入也属于交易依赖：写入失败、250ms应用等待超时或HALT导致权限代际变化后，暂停新提交；迟到成功供恢复核对使用。单写者、原100ms锁等待及有界请求继续保留，目标机器的磁盘时延需要现场复验。

本轮SQL结构维持Schema 1、六表27字段，所有新增持久载荷字段均有用途说明。正式交易记录、账单、对账和历史页面仍属于量化系统，最终由Windows日终任务回传至现有MySQL。退出状态/批次审计的中央导出映射在后续契约工作包完成；本轮共享HTTP及量化代码维持原样。

## 4 安全、兼容与改动范围

- 原BUY和dev42 SELL正文的新增默认字段在序列化时省略，旧摘要与幂等语义保持一致。`EXIT_SESSION`记录要求dev43或后续兼容读取版本，生产回退需先完成数据保全和兼容验收。
- 同日上下文更换、状态目标放宽、检查标记回退、J1引用状态缺失、过期证据、行情倒序和未来时钟均失败关闭。
- 行情、规则状态、J1以及本地授权各自有明确生命周期。数据恢复成功仍通过本次boot的恢复确认及新授权取得执行权限。
- 本轮量化后台868个基线文件新增0、修改0、删除0；本项目基线文件删除0。生产数据库、配置、QMT会话和计划任务保持原状态。
- 代码索引只缓存已验证状态摘要，避免每轮行情处理重新计算整条状态链。
