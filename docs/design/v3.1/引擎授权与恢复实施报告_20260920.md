# V3.1 引擎授权与恢复实施报告

日期：2026-09-20。程序：0.1.0.dev40。开发基线：Windows Python 3.11.16 x64。

## 1 本轮结论

本轮把此前独立验证的计划校验、最小Journal、权限闸门、SDK派发和内存预占接入一个单一状态所有者的新版引擎。新增入口可完成“启动暂停 → 券商/Journal核对 → 恢复确认落盘 → 会话授权落盘 → 模拟买入/部成/撤单 → 引擎重建 → 再核对且保持暂停”。

本轮推进R31-004/005/006及015的核心离线装配，R31-007复用已有预占组件并补充恢复观测核对。整包继续保持IN_PROGRESS，现场与正式发布门保持NOT_READY；完整持仓批次、认证IPC、任务和策略接线仍有明确工程待办。

改动范围为本自动交易项目。量化后台源文件保持原样，生产配置、数据库和任务保持原样；本轮使用Mock及专属模拟目录，真实交易关闭。

## 3 关键执行语义

### 3.1 启动与恢复

1. Mock组合根先取得账户级Windows互斥，再启动Journal owner和SDK线程。启动失败也执行已创建owner的清理；工作线程未确认退出时保留账户互斥。
2. 引擎每次启动生成新的boot ID，初始为STARTUP_PAUSED。恢复读取Journal每页200条，当前上限2048条。
3. SDK同一线程依次查询委托、成交、账户；前后比对回调序号，标识观测期间是否有新事件。当前账户观测须在5秒有效期内。
4. 核对订单归属、账户/交易日、方向/数量/价格、撤单原委托号、成交身份/金额/数量、终态以及持仓数量。查询缺失、外部订单/成交、历史归属缺口和冲突均形成BLOCKED。
5. 恢复报告与完整证据一起持久化成功后进入REVIEW_REQUIRED或RECOVERY_BLOCKED。只有CLEAR且仍新鲜的报告能进入人工确认，只有确认成功后才能申请会话授权。
6. 终态证据可释放已核实的预占和在途标记；已尝试订单ID保留，防止同ID重报。重启从Journal重建已知提交集合，数据库中旧授权保持失效。

### 3.2 人工确认与会话授权

确认凭证绑定完整请求摘要、操作员、boot、绝对截止时间及单调时钟截止时间，使用一次即消耗。发送者角色文本属于协议字段；凭证签发由可信本地认证适配器负责。

CONFIRM_RECOVERY与ARM/RESUME分成两次独立操作，各自先写关键控制记录。授权提高前再次检查：恢复报告、Journal健康、回调序号、权限epoch、截止时间、计划窗口、账户/boot、会话代际、方向、仓位及金额上限。写入等待最多250ms，期间发生急停、回报变化、磁盘失败或截止时间到达，都使该授权失败；稍后提交成功仅成为审计事实。

HALT/PAUSE先立即收紧内存权限，再异步保存审计。控制回复缓存有界；缓存满仍保留急停能力。新引擎本轮可配置PAPER/SHADOW上限，模拟SDK派发仅开放PAPER。

### 3.3 报单、撤单与回报

新买单依次校验计划、会话授权、当前账户观测、证券分配额度、整日已尝试预算、仓位数、单笔数量/金额及外部注入的纯风险规则，然后内存预占、单J1落盘、二次权限/风险核验、SDK派发。

撤单绑定已知NEW提交及已观测非终态原委托，核验券商委托号、标的、方向、数量、价格、动作目标和原计划摘要。撤单保持原订单预占，直至终态恢复核对。SDK异常按“不确定”处理并暂停，查询为空也保留不确定性。

回调仅向1024条有界队列写入不可变事实；owner每轮处理最多100条。重复事实使用内容摘要幂等落盘，迟到非终态回报保持已知终态，身份/价格/终态冲突或队列溢出触发暂停。当前关键回报逐条短事务写入；“100ms/100条批量事务”仍属于后续性能收口任务。

已尝试BUY按maximum_amount全额保守计入当日预算，包含已撤订单。后续正式费用和可退预占规则须在资金守恒/账单工作包中实现并单独验收。

## 5 故障矩阵覆盖

| 场景 | 已验证行为 |
| --- | --- |
| 授权写入延迟、磁盘异常、急停或期间收到新回报 | 权限保持关闭，迟到成功保持审计用途 |
| 超权限授权、过期/篡改确认、旧boot、请求ID冲突 | 拒绝授权或拒绝歧义请求 |
| Journal关键事实/恢复检查点写入失败 | 暂停；恢复证据失败时保持无有效报告 |
| SDK已受理但返回超时 | 保留不确定状态，查询未终结则恢复BLOCKED |
| 查询失败/查询超时 | 保持暂停，超时SDK调用的工作槽继续占用 |
| 重复委托/成交、重复Journal ID或逆序记录 | 拒绝歧义输入 |
| 外部订单/成交、价格/日期/金额冲突、终态数量矛盾、持仓缺口 | 恢复BLOCKED，要求解决证据差异 |
| 撤单使用另一券商订单号 | 拒绝进入报撤单调用 |
| 回报溢出、身份/终态冲突、撤单失败 | 立即或owner下一轮收紧权限 |
| 时钟回拨、跨交易日、会话到期 | 清除有效授权并暂停 |
| owner线程越界、重复/迟到回报、启动存储失败 | 拒绝越界、保留终态、清理已创建资源 |

## 6 已实现与尚待实现的明确界线

### 6.1 下一批可继续离线开发

1. 完整订单归约与账户观测刷新：当前新增买单使用恢复观测，回报变化或观测超过5秒即需要重新核对。下一步接入有版本的持续账户观测与严格订单状态归约，保留同一SDK线程和权限校验。
