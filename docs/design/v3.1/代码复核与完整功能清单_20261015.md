# 自动交易系统代码复核与完整功能清单

复核日期：2026-10-15。适用范围：Windows 独立交易项目，以及量化项目各层的 auto_trading 模块。

本报告对照 V3.1 详细设计、22 个工作包、dev53 离线交付记录及现有代码。代码复核重点包括订单提交许可、恢复、模拟券商事实、进程与 IPC、计划拉取、日终导出、账单核对和页面请求时序。通过静态阅读及离线回归验证当前行为；真实 QMT、券商账单及目标机运行结论仍需现场取得。

## 1. 当前实际交付状态

- 当前发行包仍为 0.1.0.dev53；本次修复在工作区源码中，前端已在独立目录构建验证，本轮没有替换既有发行包或进行生产发布。
- 新版 Windows 是一个轻量现场台，包含进程状态、计划摘要、操作员登录、本机急停及恢复/模拟授权。已有正常 engine、agent、console 进程入口。
- 量化项目当前注册两个管理员页面路由：自动交易监控、自动交易治理。每日交易记录 V2 是监控页内嵌的独立组件。
- 量化 V2 每日查询、样例账单和离线模拟交易具备工程实现；正式结算、实盘接入及全部设计页面尚未完成。
- 报备方向已明确为量化多头并可能开展底仓日内回转；具体选股、信号、仓位和做 T 规则未冻结。已有 Entry/Exit 是模拟开发基线。
- QMT 环境缺失主要阻塞真实接口适配与现场验收。下文列出的退出汇总、页面、维护和录放功能有可离线推进的部分。

状态说明：“已实现/离线通过”表示有实现和离线证据；“部分”表示只有所列子能力；“待实现”表示缺少可运行的相应业务功能；“待现场”表示尚无目标机实证。这些状态不表示已经上线。

现有路由为 `/auto-trading-monitor` 和 `/auto-trading-governance`。只有启用前端模块开关后注册，后端自动交易路由另受其模块开关控制；当前管理接口沿用管理员角色，没有完成设计中的多种细分业务角色。

旧监控的五类标签：Incident、交易计划、订单、数据同步、对账，以及节点列表、巡检、异常确认/处置。这些旧接口和页面保留兼容，但新版采用每日回传；不能把旧版实时心跳/事件监控视作 V2 engine 已实时上报。每日记录 V2 组件才读取新版日批次数据。
