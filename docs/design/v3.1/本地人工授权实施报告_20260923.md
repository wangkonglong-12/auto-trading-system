## 1 本轮完成范围

本轮将已有授权内核接入独立引擎的真实Windows通信入口。实现操作员口令校验、恢复确认、PAPER授权/恢复、受限预览、一次性人工确认、持久化结果及回执补查。operator_access可选；旧配置继续以授权关闭状态运行。

本次交付的是可运行的本地授权通路，运行档仍为MOCK且安装交易额度为0。PAPER授权APPLIED表示控制记录已持久化、权限状态已转换，实际报单仍受零额度与关闭的策略闸门约束。完整策略和行情接线、非零模拟交易与真实交易分阶段验收。

| 部分 | 具体实现 |
| --- | --- |
| 身份 | 配置固定actor_id；Windows凭据管理器保存独立scrypt校验值；IPC角色密钥与口令凭据分离 |
| 认证 | 复用已有短会话、双令牌、失败限流；每次CLI调用交互登录并在结束时退出 |
| 隔离 | 单独authorization管道执行口令计算；原control管道保持状态、急停、退出与主动核对 |
| 预览 | 服务端生成确切请求，显示账户、交易日、报告、boot、额度、方向、有效期和确认短语 |
| 确认 | 复核会话/归属/逐字短语/版本/权限代际；owner签发一次性证明并交给原控制内核 |
| 持久化 | 恢复确认与PAPER授权记录进入单Writer的control_records；成功提交后才改变授权状态 |
| 补查 | 重复确认返回原结果；新登录可按原request_id查询本boot结果，避免不确定时重复授权 |
| 重启 | 新boot从暂停恢复，旧会话、预览和授权失效；历史控制审计保留 |

架构决定见[ADR-R31-006](ADR-R31-006_独立进程人工授权.md)。新增配置及消息字段提供用途说明；SQL字段、数量、Journal角色及HTTP接口保持原样。

## 2 人工操作流程

在专属节点配置中增加operator_access，actor_id使用明确的操作员编号，password_verifier使用与IPC密钥不同的Windows凭据目标。例如：

```json
"operator_access": {
  "actor_id": "local-operator",
  "password_verifier": {
    "source": "WINDOWS_CREDENTIAL_MANAGER",
    "target": "AutoTrading/example-paper-node/operator-password"
  }
}
```

使用现有`auto-trading-credential --kind operator-password --target AutoTrading/example-paper-node/operator-password`交互设置口令。工具存储scrypt校验值。示例配置默认operator_access为null；本轮没有向本机凭据库写入实际凭据。

配置完成并重新启动引擎后，使用同一专用Windows用户的交互终端：

```powershell
auto-trading-node --config C:\AutoTrading\config\node.json recover
auto-trading-node --config C:\AutoTrading\config\node.json status engine
auto-trading-node --config C:\AutoTrading\config\node.json authorize confirm-recovery
auto-trading-node --config C:\AutoTrading\config\node.json authorize arm
auto-trading-node --config C:\AutoTrading\config\node.json halt
```

recover返回核对已开始及对应状态版本；等待STATUS为该次REVIEW_REQUIRED再确认。核对报告有30秒时效，确认短语最多20秒；过期时重新核对并核实新报告。arm默认申请BUY方向、0元买入额度、0元单笔额度、0持仓名额、60秒PAPER会话；超过安装额度的申请被引擎拒绝。

急停后采用“recover → 核对 → authorize confirm-recovery → authorize resume”重新确认。授权CLI只有最终APPLIED返回0，取消/待定/拒绝返回非成功状态。授权回执丢失时，使用预览输出中的request_id：

```powershell
auto-trading-node --config C:\AutoTrading\config\node.json authorization-result <原request_id>
```

结果查询不会恢复权限；当前状态仍看STATUS。跨boot回执不作为当前授权，需按重启恢复流程操作。
