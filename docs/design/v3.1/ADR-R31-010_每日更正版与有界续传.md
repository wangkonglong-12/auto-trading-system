# ADR-R31-010：每日更正版与有界续传

日期：2026-09-25。实现：0.1.0.dev51。范围：Windows同步工程；对应R31-010及R31-011客户端验收。

## 1. 责任和数据来源

Windows Task Scheduler继续在15:30触发`job daily-export`，15:45起每15分钟重复至18:00；08:45的`job catch-up`以及agent启动补传负责已有批次。任务注册配置保持原样。收盘刷新窗口包含18:00这一分钟，允许任务启动延迟；18:01起结束刷新。

每个收盘窗口最多发布一次新的完整观测。agent通过已认证管道请求engine核对；engine在暂停态、关键操作完成、核对报告新鲜且回报版本一致时冻结快照。快照捕获由状态所有者完成，分片和日期引用发布由管道工作线程完成；网络请求、重试任务和文件游标由agent独立完成。

每次成功刷新是一次新观测，即使数量相同也保留新的观测时间和证据编号。它表示观测证据更新，不等同于发现交易差错。已有`EXPORT_DAILY`仍只获取当前冻结版本；新增agent角色动作`REFRESH_DAILY`负责当前窗口的新观测。重复触发同一窗口复用已有版本。跨日补传上传原交易日的冻结内容，旧交易日重新取数需要独立历史事实来源。

## 2. 本地不可变日版本链

| 文件/字段 | 定义 |
| --- | --- |
| `daily-catalog/YYYY-MM-DD.json` | 首版引用；兼容dev50，内容仍为artifact_hash |
| `daily-catalog/YYYY-MM-DD.r0002.json`等 | 后续完整版本的独立引用；旧引用原样保留 |
| `revision` | 从1开始连续递增；本地每交易日上限32版 |
| `supersedes_batch_id` | 精确指向前一版batch_id |
| `data_as_of/generated_at` | 相对前一版单调不减；重传保持原值 |
| `journal_generation/last_record_seq` | 同一Journal代际内序号单调不减；跨代际更正走后续维护流程 |

账户、节点、节点代际及交易日必须一致。文件、分片和清单全部校验后才发布引用。引用通过同目录临时文件、文件同步和独占硬链接发布；并发同内容可复用，并发不同内容明确报错。当前版本通过连续引用链推导；没有可被覆盖的“最新指针”。分片缺失、hash不符、重复业务记录、记录类型/账户/日期不匹配、截止时间越界都进入错误处理。

发布边界：引用发布前中断，已生效旧版保持可发现；引用发布后回执丢失，重复调用发现相同版本。引用发布后、agent登记任务前退出，重启发现完整版本链并逐版登记。更正版是八类数据集的完整替换，而不是增量相加。

目录最多4000份引用；任务索引仍最多4000项（也包含计划回执）。每批上限16MiB、2048分片、每片200条/512KiB沿用既有约束。容量耗尽报告维护需求，保留原文件。硬链接和文件同步的真实断电耐久性仍需目标NTFS及存储设备验证。

## 3. 传输、前置版本与公平重试

每个更正版上传前校验本地直接前置版本，并向量化接口核实它的APPLIED回执。当地SYNCED不能替代该核实，因为量化数据库可能恢复到了较早备份。

- 前版远端尚无APPLIED：当前版保持PENDING，原因PREDECESSOR_PENDING，等待前版自己的轮次修复。
- 前版需要人工处理：当前版保持PENDING，原因PREDECESSOR_ATTENTION。
- 前版缺失、身份/序号冲突、回执绑定错误：当前任务NEEDS_ATTENTION。
- 暂时断网：保持PENDING；本地文件I/O暂时失败：LOCAL_STORAGE_ERROR，下轮重新核验原文件后重试。
- 内容冲突/损坏：保持NEEDS_ATTENTION，保留证据，后续维护流程负责核验与处置。

每次任务最多处理8个业务任务，HTTP总调用预算仍为90秒。每个任务只核实直接前版，避免递归遍历祖先耗尽预算。待上传/失败任务和已成功历史回执各使用独立、带校验的文件游标轮转：两类同时存在时，最多7个名额给待上传、至少1个给历史核查；只有一种时使用全部名额。预算为1的测试/内部调用使用统一轮转游标。

游标字段`after_job_id`表示已经完成本地结果落盘的任务。先保存任务结果，再原子推进游标；结果保存失败停止本轮，游标保存失败最多造成原任务重查。轮转顺序依赖稳定任务ID及已持久化游标，独立于系统时钟调整和进程重启。回执发现缺失后仍保留原batch_id、manifest_hash和分片内容，按原版本修复。恢复大量历史的时间取决于积压量、任务触发频率和远端性能，当前版本以有界公平推进为保证。

## 4. 故障隔离与状态

引擎不可达或新的核对尚未完成：保留已有批次并继续上传，任务结果为PENDING、fresh_export=PENDING。目录中新发现的无效引用：返回NEEDS_ATTENTION及DAILY_CATALOG_REVIEW；已经登记的有效任务继续重试。任务索引自身校验失败则停止任务，等待人工核验；错误不当作空索引。

已有最小SQLite Journal仍只承担关键交易与恢复事务，agent的批次、任务、回执和轮转游标采用文件。本次无SQL表、字段、共享HTTP协议或量化后台代码变更。历史交易、账单和中央查询保持在量化系统。

## 5. 兼容、验收及后续

dev51可读取dev50首版日期文件和任务记录，首次重试按需建立游标。回退dev50时保留所有新旧引用、分片、回执和任务文件；dev50只发现首版引用，因此回退不具备完整更正版发现能力，应暂停同步并核验保全，不能把旧程序的SYNCED当成所有新版本已同步。

离线验收覆盖真实Windows命名管道、双向签名HTTP客户端与内存接收端、跨窗口刷新、断网及引擎停止补传、并发发布冲突、中断、回执丢失、长链小预算、时钟回拨和远端旧点恢复。内存接收端用于本轮逻辑验收；量化生产MySQL、真实网络与目标Windows任务账号的联合验证另列现场验收。

后续工作：暂停态备份/恢复与代际维护、跨日历史事实补采、独立退出/批次审计结果、正式账单晚到与结算、人工失败任务处置入口、长期留存与容量治理。实际策略尚待确认；长期宿主继续使用MOCK券商、零额度和关闭的实盘开关。
