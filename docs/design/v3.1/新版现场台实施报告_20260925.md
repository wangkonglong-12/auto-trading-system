# 新版 Windows 现场台实施报告

日期：2026-09-25；程序版本：0.1.0.dev50；Windows Python：3.11.16。

## 1 本轮交付

本轮完成 V2 现场台离线模拟切片，接入实际引擎/监护/同步代理管道，页面与交易进程独立运行。策略仍待用户确认；长期宿主保持 MOCK 和 0 额度。

| 功能 | 本轮实现 |
| --- | --- |
| 启动入口 | `auto-trading-node --config <绝对配置路径> console --port 8780`；固定本机回环地址，账户级独立互斥 |
| 运行概览 | 实际引擎状态、恢复核验、暂停原因、关键存储健康；监护状态/失败数/原因；代理最近任务结果 |
| 计划摘要 | 当前已加载计划、标的、技术策略标识和交易日；显示尚未加载的真实空状态 |
| 状态可信度 | 标明观测时点、过期、失联；基于主循环序号识别“管道有响应但 owner 停止推进” |
| 操作员访问 | 引擎验证登录、会话刷新恢复、退出、过期失效；未配置访问时页面保持只读 |
| 急停及恢复 | 已认证急停使用独立管道，恢复核验通过 owner 队列执行前再次验证 |
| 模拟授权 | 恢复确认、ARM/RESUME 的范围预览、逐字短语确认、持久化回执和原请求补查；服务端固定零额度 |
| 异常保护 | 请求超时保留原编号；标签页刷新继续补查；状态失新或编号保存失败锁定授权；急停使迟到预览失效 |
| 兼容性 | 旧 V1 页面和接口保留，新旧页面采用独立入口，随同一个发行包提供 |

页面没有伪造资金、持仓或历史交易信息。交易记录、账单、中央账本与历史查询的正式使用位置仍是量化系统。

## 2 主要工程文件

- `apps/local_console/node_app.py`：V2 本机 HTTP 入口、会话 Cookie、请求校验、安全响应头及服务启动。
- `apps/local_console/node_bridge.py`：HTTP 到认证管道的转换、独立控制通道、并发预算。
- `apps/local_console/node_status.py`：三个固定探测线程、字段白名单、身份和主循环进度校验、内存观测缓存。
- `control/node_authorization.py`、`runtime/node_engine.py`：新增会话恢复和已认证现场控制动作，补充计划/限额摘要。
- `frontend/operator-console/src/node`：V2 页面、限时请求、原请求跟踪和独立样式；`node.html` 为新入口。
- `tests/v31/test_node_console.py`、`frontend/operator-console/src/test/nodeConsole.test.ts`：真实命名管道/HTTP 专项和页面交互专项。

上述 Python 文件相对于 `src/auto_trading_system`。完整改动清单见证据目录中的边界比较文件。

构建时 Vite 会替换输出目录内带哈希的静态文件。因此最终全量 Python 测试在前端构建完成后运行，避免同时读取正在被替换的资源。旧生成资源变化与业务源码删除分别核对。

## 4 启动与使用

1. 使用已经初始化的 V2 节点配置和对应专用运行用户。配置示例为 `config/v2/node.mock.example.json`；示例 SID、路径、可信密钥和日历需要按部署对象填写。
2. 启动引擎或其监护进程；同步代理单独启动。运行现场台命令后，在浏览器打开 `http://127.0.0.1:8780/`。
3. 先核对节点/账户和各组件状态。页面显示“状态已更新”仅代表当前观测满足要求；计划、同步和 QMT 准入分别检查。
4. 配置 `operator_access` 后，使用操作员口令登录。点击恢复核验后观察状态变化；确认恢复和模拟授权均核对预览，再输入确切短语。当前授权金额/持仓额度为 0。
5. 如果确认结果丢失，使用页面上的“查询原请求结果”。页面保留编号，刷新不会自动重发。跨引擎启动的旧请求未知结果按人工核验处理。
6. 急停成功表示新派单闸门已锁定。在途委托继续按券商事实核对。关闭页面或现场台服务，交易进程保持独立。

工程说明及具体协议见 [ADR-R31-009](ADR-R31-009_新版现场台与进程控制边界.md)。
