# 买入持续驱动实施报告

日期：2026-09-23。程序：0.1.0.dev48。Windows验证基线：CPython 3.11.16。

## 1 本轮完成内容

本轮完成买入主流程的持续驱动切片，覆盖冻结目标、无订单跳过、按rank多标的调度、受限拆单、撤单核对、部分成交补单、重启恢复及日终结果导出。架构和字段定义见[ADR-R31-007](ADR-R31-007_买入目标与受控补单.md)。

| 功能 | 已实现行为 |
| --- | --- |
| 策略与计划绑定 | 完整策略正文hash/version、规则包版本和证券集合匹配签名计划 |
| 一次目标 | 首次目标或零目标跳过独立保存；后续报价和重启保持原决定 |
| 限价与拆单 | 合法数量、单笔额度、追价/价差、价格范围、盘口及参与量共同限制 |
| 持续调度 | 最多15个非空计划标的按rank处理；最高3个活动订单；每分配最多4个子单 |
| 受控补单 | 订单、成交及账户一致且解除预占后回收未成交本金；未知结果保留完整占用 |
| 重启 | 恢复目标和J1次数，旧授权失效，重新核对和本地授权后继续剩余目标 |
| 日终 | 无单跳过输出SKIPPED和原因；实际目标随冻结快照交给现有每日上传链路 |
| 整体业务组合 | 已将两天业务验收的D0手工构造订单替换为Entry owner驱动，继续D1卖出及回传 |

新增模型字段均带说明，关键恢复与并发边界有代码注释。当前成交量控制采用当日尝试量扣减最新60秒容量的保守口径；10秒加速、精确滚动容量和正式行情适配继续单列，见第4节。

## 2 可复现业务证据

```powershell
.\.venv\Scripts\python.exe -m auto_trading_system.apps.trade_runtime --simulate-entry-owner .codex_tmp\entry-demo
.\.venv\Scripts\python.exe -m auto_trading_system.apps.trade_runtime --simulate-business-flow .codex_tmp\business-demo
```

入口固定Mock券商、模拟交易日和测试授权。每次新建专用子目录，保留Journal和JSON结果。

买入恢复案例：固定目标100股，首子单100股实际成交40股；价格变化触发撤单，订单/成交/账户核对后关闭内核。重新打开同一Journal时目标原样恢复且保持暂停；重新核对授权后补60股，最终100股。保守累计金额为1010元（1000元本金加两笔各5元预留），目标和实际成交均未放大。

多标的测试使用三个明确Mock证券，验证rank顺序、两活动单上限及三标的全成交后的独立持仓；无单目标、最小金额跳过、次数耗尽、低容量等待和停止窗口撤单分别测试。旧买入绑定、既有D1退出、权限与进程路径继续回归。
