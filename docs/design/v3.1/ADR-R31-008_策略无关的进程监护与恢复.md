# ADR-R31-008 策略无关的进程监护与恢复

日期：2026-09-23。版本：0.1.0.dev49。范围：Windows 自动交易项目，R31-004/015 的进程监护切片。

## 1 决策与策略边界

用户已明确实际交易策略尚未确定。Entry/Exit 基线保留为模拟与回归样例；正式买卖条件、仓位、追价与残仓规则在业务确认后冻结。当前优先完成运行、操作、同步和恢复能力。监护配置仅控制运行健康与重试，不定义买卖策略，也不签发交易授权。

新版进程入口使用 `auto-trading-node --config <绝对配置路径> supervise`。监护器拥有一个交易子进程；现有独立 agent 和 Windows 数据同步任务继续工作。Engine 任务名称保持原值，生成的启动命令改为 supervise。任务生成与实际注册分开，现有系统任务保持原状态。

## 2 分层与进程所有权

| 模块 | 职责 |
| --- | --- |
| runtime/node_supervisor.py | 单所有者健康状态机、退避与熔断、认证控制入口和启动装配 |
| runtime/owned_process.py | 持有真实 Windows 进程/Job 句柄，创建、归属验证及定向停止 |
| runtime/supervision_state.py | 小型监护恢复文件、原子替换与人工重置前证据归档 |
| runtime/node_engine.py | 仅由交易主循环发布进度序号；接受绑定启动身份的停止请求 |
| config/node_v2.py | 有注释的运行健康配置，沿用受保护目录与凭据引用 |

监护器使用账户范围的独立互斥锁；启动前验证当前账户没有独立 engine。已有 engine 持续保有自己的账户锁。即使检查与创建之间发生竞争，第二个 engine 也会因账户锁拒绝启动，监护器只收尾自己创建的子进程。

使用随机唯一 Windows Job 名称并检查名称碰撞。子进程先以挂起、隐藏窗口、句柄不继承方式创建，分配到 Job 后才恢复运行。Job 配置 KILL_ON_JOB_CLOSE。停止范围来自持有的句柄；进程名称、磁盘 PID 文件均不用于寻找或终止程序。Windows 虚拟环境可能启动真正的 Python 解释器，因此认证回复中的实际 PID 必须属于本次 Job，而不是简单等于启动器 PID。

Windows 接口依据：[CreateJobObjectW](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-createjobobjectw) 与 [pywin32 CreateJobObject](https://timgolden.me.uk/pywin32-docs/win32job__CreateJobObject_meth.html)。实现使用项目现有 pywin32 依赖。

## 3 主循环进度与通信

Engine 的认证 STATUS 增加 node_id、account_id、node_generation、process_id、supervision_id 和 owner_sequence。owner_sequence 仅在交易所有者发布快照时递增；认证管道工作线程只返回缓存副本。管道还能回复而主循环停止推进时，仍会触发超时。

监护器依次核对 HMAC/请求绑定、节点/账户/代际、运行模式、启动身份、Job 归属、boot_id 和递增序号。重复序号不刷新计时；序号倒退、身份变化或 Journal 不健康会停止受控子进程并锁定。所有超时和退避使用单调时钟；状态时间不作为进度证据。

每次底层监护管道交换预算 0.5 秒；一次 STATUS 包含握手和查询两次交换。已有普通调用继续使用原 7 秒默认值。监护器的 STATUS/STOP 使用独立 supervisor 管道，与交易授权管道分离。该管道只开放 HELLO、STATUS、STOP。

## 4 故障状态和恢复

| 场景 | 行为 |
| --- | --- |
| 初次启动 | 先持久化启动身份，再创建进程，等待实际主循环进度 |
| 异常退出、首次进度超时、主循环停滞 | 关闭本次受控进程，记失败，指数退避后启动新进程 |
| 连续或跨重启累计失败达到阈值 | 保持 BLOCKED，等待停机人工维护重置 |
| 磁盘低空间/查询失败、身份异常、恢复库异常 | 关闭受控进程并锁定，不因稍后健康恢复自动清除 |
| 故障证据无法写入 | 受控进程仍先被停止；保留旧启动中证据，监护退出 |
| 监护进程被强制结束 | Job 句柄关闭终止已归属的子进程；下次启动将未收尾启动记为一次失败 |
| 操作员正常停止 engine | 子进程退出码 0，监护正常退出，不重新拉起 |
| 操作员停止 supervisor | 先发送绑定 supervision_id 的停止请求，限时等待，再以自有 Job 定向收尾 |

默认运行参数：检查间隔 1 秒，首次进度等待 30 秒，进度停滞阈值 10 秒，停止等待 5 秒，初始退避 2 秒（最高 30 秒），累计失败阈值 3 次，最低磁盘可用空间 256 MiB。失败预算跨正常启动和进程崩溃保留；人工维护重置后清零。这些都是工程默认值，目标环境按启动时长和磁盘情况复验。

新 engine 走现有恢复状态机；旧 boot 的授权失效，新的恢复核对及人工确认仍需完成。当前宿主保持 MOCK 和零安装额度。监护器的 HEALTHY 仅表示主循环有进度，不表示可以交易或 QMT 可用。

## 5 持久化与人工维护

监护状态保存到受保护数据目录的 `critical/supervision-state.json`，不进入普通日志轮换目录。它是进程监护恢复记录，不是交易历史。文件包含范围摘要、累计失败、熔断标记、未收尾启动身份、固定原因码和上次重置归档摘要。字段定义在代码中有说明。

写入采用专属临时文件、flush/fsync 和同目录原子替换。重置先将完整旧状态写入现有不可变 artifacts，再保存引用与清零状态。损坏、超限或范围不匹配的状态拒绝使用。新增 SQL 表和字段均为 0；Tick 和正常健康轮询不写 SQLite。

维护操作：

```powershell
auto-trading-node --config C:\ATS\node.json status supervisor
auto-trading-node --config C:\ATS\node.json stop supervisor
auto-trading-node --config C:\ATS\node.json reset-supervision
auto-trading-node --config C:\ATS\node.json supervise
```

以上是命令模板，不是已部署路径。reset-supervision 要求配置的 Windows 服务身份、engine 与 supervisor 均已停止，以及交互式输入完整的账户确认短语。它只清除运行重试预算；交易授权沿用独立的口令与确认流程。

## 6 验收范围和剩余边界

本轮验证 Mock 宿主、真实 Windows 进程、真实认证管道、Job 所有权、正常停止、强杀与卡死恢复。业务策略、真实 QMT 及非零额度保持原状态。账单、每日历史继续在量化系统承接。

目标 QMT/Windows 登录会话、计划任务现场安装、全天负载、运行中的真实 SDK 强杀及订单未知结果联合恢复，需要后续目标环境验收。创建挂起子进程到分配 Job 之间发生监护器外部强杀的极小窗口，可能留下尚未运行的挂起进程；该窗口不执行交易代码，仍列入后续启动原子性专项，不将本轮结果表述为全部指令点强杀已验收。

下一项是 Windows 现场台绑定新版进程状态和授权结果。通用行情录制/回放、日终更正版与补传核对、备份恢复和账单导入按独立工作包继续。正式策略宿主接线以策略确认作为前置条件。
