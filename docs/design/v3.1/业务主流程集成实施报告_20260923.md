# V3.1 业务主流程集成实施报告

日期：2026-09-23。交付版本：0.1.0.dev45。环境：Windows、Python 3.11.16。

## 1 本轮结论

本轮完成一条使用同一账户、同一Journal和同一持仓批次的两天业务集成链路：计划拉取、引擎加载、D0买入、封存、D1恢复卖出、日终回传及测试接收端查询。

同时交付可复用的计划线程交接、买入目标J1绑定、引擎日终快照和八类数据映射组件。不是将几份独立演示的结果拼成报告；回传的委托、成交和账户值来自这条链路中引擎实际取得并完成恢复核对的Mock事实。

这是离线业务贯通验收。券商使用Mock，HTTP使用签名客户端配合MockTransport，接收端为内存测试实现。正式独立进程、认证IPC、Windows任务注册、量化查询页面、正式账单及真实QMT仍有明确待办，不能将本轮结论记成生产系统已经完整可用。

## 2 主流程实际结果

| 环节 | 本轮实际行为与检查 |
| --- | --- |
| 拉取计划 | 从未预加载计划的引擎启动；agent线程调用签名HTTP接口、验签和保存文件，owner加载并形成回执；重复任务保持同一回执，加载后保持暂停 |
| D0买入 | 测试操作员完成恢复确认和PAPER授权；复用数量/价格规则，冻结100股目标；J1成功后Mock成交100股 |
| 收盘与回传 | 15:01重新核对并冻结日终快照，封存100股；15:30模拟任务冻结文件并上传；远端APPLIED后故意丢弃回执，重新创建agent后补查成功 |
| D1卖出 | 同一Journal恢复相同批次ID，启动保持暂停；独立退出上下文及SELL授权后，由持续D1 owner触发并完成100股模拟卖出 |
| 次日回传 | D1再次收盘核对、导出和上传；既有D0成功批次仍可重查；两天数据属于各自明确交易日 |
| 接收端查询 | 查询实际应用版本中的BUY/SELL各100股、资产和数据状态，最终剩余持仓0；相同日期未完成上传的新版本不影响旧版本查询 |

Mock账户资金延续：初始现金10,000元；D0买入后现金9,000元、证券市值1,000元；D1按样例10元成交卖出后现金10,000元、证券市值0。D1沿用D0收盘现金，避免把样例账户重新初始化成10,000元导致虚增资产。

行情、成交价格、估值、交易日历及费用假设属于明确测试样本，不是收益或真实账单证据。两天财务状态均为PROVISIONAL，现金结算结果为INDETERMINATE。D0八类数据已取得；D1独立退出策略结果契约待扩展，因此业务状态明确为INCOMPLETE，成交、委托和资产仍可查询。

## 3 组件和职责

| 组件 | 已实现职责 | 保持的边界 |
| --- | --- | --- |
| PlanDeliveryMailbox | 有界队列、owner执行、回执、超时/关闭/容量保护 | 网络在agent线程；进程内交接与认证IPC分别验收 |

## 4 安全和兼容

- 引擎owner不执行HTTP请求；网络超时和上传回执丢失与引擎交易权限分离。计划交接超时发生在领取前会取消，发生在领取后记为结果不确定，按原计划身份重试。
- 后续买入子单不能扩大、替换或移除已冻结的买入绑定；累计尝试数量受实际目标限制。部分成交后的买入补单策略仍待正式完整策略验收。
- 拒单、部分成交后撤单和全部成交分别生成相应计划结果；未取得实际目标时保留缺口，不用数量上限替代实际目标。无法核对的提交结果保持UNCERTAIN。
- 旧J1无entry_binding时，序列化省略新字段，旧正文摘要保持兼容。新绑定字段和新增账户持久载荷字段都有用途注释。SQL继续六表27字段，共享HTTP契约源文件保持原样；本地提交Schema已重新导出。
- 本轮同一字段在不同组件间保持明确意义：交易日、数据截止时间、实际目标、现金/市值、数据完整性与财务状态分别保存。旧程序读取新载荷前要验证兼容，应用回退保持数据保全。

设计决策见[ADR-R31-005](ADR-R31-005_主流程交接与日终快照.md)。原Word保持V3.1基线，工程增量在Markdown主方案、ADR和本报告中记录。
