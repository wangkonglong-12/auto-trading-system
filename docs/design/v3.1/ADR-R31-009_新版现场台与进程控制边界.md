# ADR-R31-009 新版现场台与进程控制边界

日期：2026-09-25；实现版本：0.1.0.dev50；状态：已实现离线模拟版本，现场准入待验收。

## 1 职责和技术选择

Windows 使用 Vue 3 + TypeScript 页面，由独立 FastAPI/Uvicorn 进程提供静态资源和本机接口。页面承担进程观测、当前计划摘要、同步任务结果和现场控制。交易记录、账单、中央账本、对账和历史统计继续由量化系统提供。

入口为 `auto-trading-node --config <绝对配置路径> console --port 8780`，地址为 `http://127.0.0.1:8780/`。端口范围 1024–65535；服务固定绑定 IPv4 回环地址。每个账户使用独立的现场台互斥锁。现场台、引擎、同步代理和监护拥有各自生命周期；现场台退出只关闭自身资源。

Vite 采用双入口：旧 `index.html` 保留 V1 兼容，新 `node.html` 对应 V2。V2 服务根路径提供新版页面，接口统一为 `/api/v2/node`。CLI 仅在启动现场台时导入 Web 装配，交易进程启动不依赖页面资源加载成功。发布和测试顺序为“前端构建完成 → Python 全量回归 → 制品构建与安装验证”，避免构建输出替换期间进行资源读取。

当前配置固定 MOCK。实际策略仍待用户确定；安装买入金额、单笔金额及持仓额度均为 0。页面中的模拟授权用于验证控制链路。

## 2 状态观测

现场台使用操作员 IPC 凭证，通过既有 ACL/HMAC 命名管道读取状态。引擎、监护、代理各有一个固定后台探测线程；每次探测结束后等待 1 秒再发起下一次。每个管道交换限制 0.5 秒，一次 RPC 最多两次交换。HTTP 状态请求仅复制内存观测缓存，浏览器数量不会增加交易主循环的查询工作。

引擎状态由其 owner 发布。现场台校验节点、账户、部署代际、MOCK 标识、启动编号和主循环序号；同一启动编号内的序号倒退按异常处理。

| 状态 | 条件 | 页面行为 |
| --- | --- | --- |
| CURRENT | 最新观测及主循环进度均在 5 秒内 | 展示最新观测，已登录者可进入预览 |
| STALE | 观测过期或主循环序号连续 5 秒未推进 | 明确标记过期，锁定授权入口 |
| UNAVAILABLE | 尚无观测、通信失败或身份/进度异常 | 保留并标注上次观测，锁定授权入口 |

浏览器按“上次请求完成后再等 1 秒”的方式刷新；本页超过 5 秒未成功收到状态时也锁定授权。页面关闭会取消其网络请求和计时器。急停保持独立可尝试，最终结果以引擎回执为准。

返回字段使用白名单，包括引擎状态、恢复核验、暂停原因、存储健康、计划摘要、监护失败数/原因、代理最近任务结果。观测时点和失败标记一起展示；旧数据不会被解释为当前健康。代理有响应仅说明本地代理管道可达，量化接口连通性与远端数据接收应依据具体同步任务及回执判断。

## 3 登录与请求边界

操作员口令及会话沿用引擎现有认证管理器。现场台只持有 IPC 凭证，浏览器获得短会话的安全 Cookie；登录本身不产生交易授权。

- 口令只提交给本机接口，经独立授权管道由引擎验证；请求体最大 8 KiB，口令最大 128 字符。
- 会话和 CSRF 恢复凭据分别放入 `HttpOnly`、`SameSite=Strict`、浏览器会话期 Cookie；`SESSION` 同时验证这两项后，将 CSRF 值交给当前页面内存。
- 变更请求要求确切的 Host、Origin、`Sec-Fetch-Site: same-origin` 和显式 `X-CSRF-Token`；引擎再次验证会话及 CSRF。
- Cookie 随浏览器会话保存；页面的 `localStorage/sessionStorage` 不保存口令、令牌、确认短语或交易授权。引擎重启或会话过期会使原凭据失效。
- 页面资源应用 CSP、禁止嵌入框架、禁止 MIME 嗅探、禁止缓存；响应只返回稳定原因码，验证失败不回显口令或原始异常。
- HTTP 并发上限 32；授权通道最多两个已接纳调用，控制通道一个，达到容量立即返回忙碌。状态探测使用单独固定线程。

该边界面向专用 Windows 用户和单账户现场部署；操作系统管理员及同一运行用户拥有的本机进程不属于 Web 隔离能够防御的敌对主体。浏览器侧两个 Cookie 均为回环 HTTP 会话 Cookie，实际机器及浏览器组合须在部署验收中验证。

## 4 控制接口和结果语义

| 接口 | 引擎动作 | 确认方式及结果 |
| --- | --- | --- |
| GET `/status` | 后台 STATUS 缓存 | 只读观测，无授权副作用 |
| POST/GET/DELETE `/session` | LOGIN / SESSION / LOGOUT | 引擎管理短会话；刷新恢复会话；退出使会话失效 |
| POST `/control`，HALT | OPERATOR_HALT | 登录与 CSRF 验证后立即锁住新派单；返回锁定回执 |
| POST `/control`，RECOVER | OPERATOR_RECOVER | owner 队列执行前再次验证会话；返回核验请求状态版本 |
| POST `/preview` | PREVIEW_CONTROL | 生成绑定当前 boot、状态版本、恢复报告和权限代际的预览 |
| POST `/confirm` | CONFIRM_CONTROL | 人工逐字输入确认短语，沿用持久化控制链路 |
| POST `/result` | CONTROL_RESULT | 仅查询原请求；返回 APPLIED / REJECTED / PENDING 或未知原因码 |

急停通道不执行口令哈希，也不等待交易 owner。一次急停成功表示新派单已被锁住；券商侧在途订单的成交/撤销仍须后续核对。RECOVER 成功返回只代表开始核验；页面通过后续状态查看是否完成。

授权流程顺序：恢复核验 → 预览确认恢复 → 输入确切短语 → 查询持久化结果 → 预览模拟 ARM/RESUME → 再次输入短语。预览展示账户、启动编号、状态版本、权限代际、报告/执行范围摘要和期限。HTTP 层只接受动作，模拟额度由服务端固定为 0、方向 BUY、最长 60 秒；任意附加额度字段会被拒绝，引擎安装限额仍独立校验。

确认发送之前，页面把原请求编号写入按节点/账户区分的标签页 `sessionStorage`；此处只保存编号。写入失败则锁定确认。发送后立即关闭预览、禁止重复授权，若响应丢失就查询原编号。APPLIED/REJECTED 回执匹配原编号后清除待确认标记；PENDING、未知结果或通信异常保留标记。刷新继续原编号补查，关闭标签页前提示保留编号。前端任何网络超时都不会自动重发确认。

急停会立即使页面中未完成预览的迟到响应失效；已发送的确认仍保留原编号供补查。后台最终依据引擎权限代际和状态版本判定，页面状态不是授权依据。

## 5 数据和兼容性

本轮保持数据库结构原样。引擎既有 Journal 继续承担必要的控制/恢复持久化；现场台自身只使用内存状态缓存。计划摘要来自已验证、已加载的内存对象；展示不读取 Tick 数据库。

旧 V1 页面、接口、命令及资产入口保留；V2 增加 `SESSION`、`OPERATOR_HALT`、`OPERATOR_RECOVER` 和 STATUS 摘要字段。已部署的定时任务、生产凭据及量化后台文件保持原状态。

## 6 后续验收边界

1. 操作台服务、引擎、代理、监护在实际运行用户会话中的启动与断开恢复，Cookie、浏览器版本和开关机演练。
2. 引擎重启后的旧控制结果人工核验与历史查询。目前结果补查沿用同一 boot 的已确认请求范围；跨 boot 未知结果保持人工核验，页面不会自动解除待确认状态。
3. 监护熔断重置继续使用已实现的停机维护 CLI；页面展示原因，维护重置与进程启停页面另行设计。
4. 策略确定后再定义方向、额度、交易参数和正式授权页面；当前零额度模拟链路与真实准入分开验收。
5. 真实 QMT、券商委托、撤单、账单和跨日运行依赖目标环境；本轮测试不替代这些现场证据。

实施结果见《新版现场台实施报告_20260925.md》，当前任务状态以主开发计划和 R31 看板为准。
