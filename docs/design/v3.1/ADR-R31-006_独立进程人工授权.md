# ADR-R31-006：独立引擎的人工恢复确认与PAPER授权

日期：2026-09-23。状态：实施。版本：0.1.0.dev47。

## 决策

本机通信身份与业务操作授权分两层实施。角色HMAC和Windows管道ACL验证调用进程；独立scrypt口令验证操作员。操作员身份来自受保护的节点配置，服务端生成请求、授权编号和会话代际。同步代理继续只承担计划和日终职责。

引擎增加独立authorization管道，使用operator通信角色。现有control管道继续承担状态、HALT、STOP和恢复请求。口令计算在authorization工作线程执行；预览、一次性确认和权限变更通过有界邮箱交由引擎owner处理。两条管道分别接受连接，急停先锁存权限。

人工流程采用“交互口令 → 确切影响预览 → 逐字确认 → Journal提交 → 最终回执”。预览固定账户、交易日、恢复报告、boot、状态版本、权限代际、动作、额度、方向和期限。有效期取20秒、恢复报告30秒有效期和申请会话截止时间中的最早值，同时使用单调时钟限制等待。

确认时再次检查操作员会话、预览归属、逐字确认、权限代际和引擎前置条件。随后由已有OneShotApprovals签发一次性证明，已有EngineKernel.control完成持久化后授权。公共preview_control统一预览和提交时的前置检查。报单闸门、Journal提交确认和策略风控继续独立生效。

## 幂等、恢复和资源预算

- 引擎同boot最多保留128份有效预览或已确认回执索引。过期未确认预览可回收；已确认项保留用于结果补查。容量耗尽返回明确错误，HALT仍可用。
- 相同已确认预览再次确认返回已有控制回执。CONTROL_RESULT按原request_id只读查询；操作员重新登录后可查询其本boot结果。结果APPLIED描述当时动作已生效，当前权限以STATUS为准。
- 重启后操作员会话、预览和一次性授权全部重建，引擎恢复为暂停。旧控制审计保存在Journal，旧boot授权不会重新赋予权限。
- 会话复用已有实现：空闲15分钟、绝对60分钟、最多4个会话；5次失败后按5分钟窗口限流。CLI每次调用交互登录，结束时退出；口令和令牌仅在受ACL保护的本机通道及内存中传递。
- CLI在交互终端读取口令与确认短语，输出安全预览和回执。脚本参数、任务定义与审计记录只保存身份引用及动作证据。

## 发布边界

本轮开放CONFIRM_RECOVERY、PAPER ARM/RESUME。节点安装额度继续为0，broker固定MOCK，risk_guard保持关闭；实际策略、行情及非零模拟额度的接线单独验收。真实券商和ASSISTED/LIVE权限沿用独立准入门。

operator_access为可选配置。旧配置保持授权入口关闭；配置开启需新建独立口令校验值引用并重启引擎。Windows数据目录归属标记、SQL六表27字段、共享HTTP契约及原J1格式保持兼容。本轮变更只涉及Windows项目。

配置兼容方向为新版读取旧配置。旧版严格配置解析器无法识别operator_access，回退dev46时使用保留的旧版配置副本；Journal与历史审计保留，按旧版暂停恢复流程重新核对。
