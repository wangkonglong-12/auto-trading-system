# 维护备份与恢复实施报告

日期：2026-09-26。版本：0.1.0.dev52。设计：[ADR-R31-011](ADR-R31-011_维护备份与受控恢复候选.md)。

## 1. 本轮实际新增

这轮交付三个可执行命令，而不是继续修改每日同步：

| 命令 | 交付结果 |
| --- | --- |
| backup | 在停机维护窗口生成带WAL已提交事实的Journal快照，同时保存同步分片、版本目录、回执任务、重试游标及监护状态；输出固定清单摘要 |
| verify-backup | 对照备份时保存的摘要，检查完整文件目录、长度/hash、数据库结构/账户/J1正文/动作目标/证据正文 |
| restore-backup | 交互确认后写入全新私有目录，复核恢复文件，生成待核验候选副本；原目录和备份原样保留 |

已实现的安全边界：账户和监护互斥、agent任务租约；已有目录和链接拒绝；严格产品路径白名单；文件/总量/复制时间限制；中断保留部分证据；候选副本先写启动阻断标记，完成或未完成的恢复都保持禁止启动。

SQL六表及字段定义保持原样。新增维护清单及字段带中文用途说明。当前程序继续MOCK、零额度和实盘关闭；交易策略尚待确认。

## 2. 操作步骤

1. 对账户执行既有急停操作，核实在途情况，停止监护与引擎，等待agent当前同步任务结束。程序通过独占锁再次验证运行状态。
2. 用原节点配置执行备份：

```text
auto-trading-node --config <配置绝对路径> backup --destination <全新备份目录>
```

3. 把返回的manifest_hash保存到独立运维记录；随后校验：

```text
auto-trading-node --config <配置绝对路径> verify-backup --bundle <备份目录> --manifest-hash <原摘要>
```

4. 恢复演练或原数据盘不可用时，在新目录生成候选副本：

```text
auto-trading-node --config <配置绝对路径> restore-backup --bundle <备份目录> --manifest-hash <原摘要> --destination <全新恢复目录>
```

当前终端需逐字输入`RESTORE CANDIDATE <账户别名>`。成功返回CANDIDATE_VERIFIED和startup_blocked=true。

5. 候选目录保留restore-pending.json；正式运行接管以独立核验与激活流程为准。候选目录属于待验收数据，不等同于可以重新开启交易。旧版程序也不应用于启动该目录。

备份目的地的父目录须存在，且与原目录互不包含；程序只为新建目录配置私有权限。备份失败留下的目录可供检查，本次命令不会删除它，也不会覆盖重用。
