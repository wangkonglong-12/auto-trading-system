# ADR-R31-001：首批改造边界与运行基线

日期：2026-09-07。状态：采纳用于离线改造；真实接入仍受V3.1验收门约束。

## 背景

旧版已有代码和测试，目标QMT环境暂缺。两项目都存在未提交文件，量化项目还有与自动交易无关的用户改动。新版调整本地存储与每日回传方式，需要明确过渡路径和可验证的删除边界。

## 决策

1. Windows采用CPython 3.11 x64生产候选基线，在独立3.11.16环境验证；开发兼容3.12，量化现有Python及依赖保持原样。Word和Markdown统一该口径。目标XtQuant wheel与3.11兼容性通过现场探针确认。
2. 新最小Journal使用APSW 3.53.4.0内含SQLite 3.53.4，锁文件固定wheel hash。应用检测实际版本、库身份、Schema和账户。新Journal采用独立路径，与旧库明确隔离。
3. Journal单写者通过有界邮箱服务engine。J1异常、超时或迟到证据使提交停止；已有提交在恢复核对后处理。逻辑容量耗尽时保留原始SQLite错误，按实际事务状态回滚。
4. 已有业务装配继续保留；新增组件先进入固定Mock的单入口演示。真正的V2入口完成后按逐文件依赖检查替换旧模块。测试用模拟接收器保持在testing目录。
5. 量化首批采用新增文件方式交付V2日终服务、存储适配器和增量SQL。HTTP注册、任务注册、正式发布开关与数据库迁移留待各自测试通过后接入。改造前文件哈希用于证明既有量化文件保持不变。
6. 量化日版本APPLIED仅证明原始记录完整可见；费用及账单采用PROVISIONAL，账本和SETTLED由后续正式对账模块产生。
7. 工作包区分实现、隔离测试、现场和发布状态。局部组件通过测试不将整包改为DONE，也不将全部工程待办归因于QMT缺失。

## 影响与验收

短期同时存在V1与V2实现，README、入口参数和状态看板明确其用途；新版生产切换前持续保留旧回归。每轮按原文件hash和精确新增清单复核量化边界。

开发机短时延迟和进程崩溃测试属于工程证据，真实存储介质、两交易日组合负载与QMT语义仍须复验。依赖版本升级要重新锁定和执行相关矩阵。
