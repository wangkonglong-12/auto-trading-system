## 2. 实现架构及数据归属

量化服务继续使用现有MySQL，由独立auto_trading模块保存已上传日版本、业务记录、样例账单和核对结果。
Windows任务入口请求agent执行拉取与回传；agent负责HTTP签名、下载、冻结文件及断点重试；engine负责唯一交易状态、许可、策略驱动和券商调用。现场台继续提供运行状态、恢复确认、授权和急停。

Windows存储划分：

| 存储 | 用途与边界 |
| --- | --- |
| 内存 | 最新模拟行情、盘中计算及工作队列；本版持续驱动使用明确给定的虚构报价 |
| SQLite关键Journal | 沿用已有最小提交/恢复证据及独立写入者；本轮保持现有SQL六表及提交许可门 |
| artifacts、daily-catalog、jobs | 已验签计划、不可变日终分片、当前日版本引用、上传回执与重试进度 |
| critical/plan-recovery.json | 已接受计划的摘要引用；重启核对时恢复签名归属，即使已过报单截止；当前时限和本地授权仍由交易许可链检查 |
| critical/paper-broker.json | 仅MOCK使用的独立虚构券商委托、成交及编号序列；模拟接受/成交先保存，再回调；用于验证“本地意图”和“券商事实”独立恢复 |

模拟券商文件上限8MiB、2048笔委托、4096笔成交；保存使用新临时文件、flush/fsync和原子替换，失败保留原文件。校验账户、初始资金、编号序列、成交所属委托及数量。它只承担模拟券商职责，真实QMT事实将来自实际券商查询。
两项新增关键文件已纳入现有停机备份白名单。备份恢复候选仍遵循dev52的核验及启动阻断。

## 3. 明确的测试会话与安全默认值

旧配置保持兼容：broker=MOCK，paper_session缺省，额度0。显式模拟配置具有以下全部条件：

1. account_id使用paper-前缀；配置operator_access及独立口令校验值。
2. paper_session.label=FICTIONAL_ACCEPTANCE_ONLY，limits.mode=PAPER。
3. as_of显式使用+08:00并属于已安装交易日历。本版采用固定模拟时刻，推进至收盘或次日时停止并重启进程。
4. prices完整覆盖测试标的。ENTRY携带EntryPolicy；EXIT携带已封存opening和签名ExitSessionContext。
5. 本地模拟最大买入金额、单笔金额各不超过100000元，单笔股数不超过10000；实际权限还受计划、风控和本地授权共同约束。
6. 每次启动保持暂停，重新登录、核对、确认并授权。配置本身只提供模拟输入和上限。

完整字段定义见config/v2/node-config.schema.json及config/paper_session.py中的中文说明。
正式策略尚由业务确定；本次100股、10元买入和10.7元退出均为虚构验收输入。

## 4. 安装与操作

### 4.1 Windows安装包

发行包位于dist/auto_trading_system-0.1.0.dev53-py3-none-any.whl。
使用单独的Python 3.11 x64环境，本次实测3.11.16；量化后台本次使用其原有3.13.13环境，两端通过HTTP契约交互。

```powershell
# 在新建的交易节点虚拟环境中执行；Python代表该环境的解释器。
python -m pip install --require-hashes -r requirements/runtime.lock
python -m pip install --no-deps dist/auto_trading_system-0.1.0.dev53-py3-none-any.whl
python -m pip check
```

按node.mock.example.json填写专属数据目录、实际SID、凭证引用、日历、公钥及策略版本；测试模拟会话使用第3节字段。首次执行init创建全新受保护目录。

```text
auto-trading-node --config <配置绝对路径> init
auto-trading-node --config <配置绝对路径> check
auto-trading-node --config <配置绝对路径> engine
auto-trading-node --config <配置绝对路径> agent
auto-trading-node --config <配置绝对路径> console --port 8780
```

后三项各自运行在独立进程；现场台地址为http://127.0.0.1:8780/。当前现场台保持原有零额度表单；本轮非零模拟额度使用下面的交互CLI，既有口令、预览和逐字确认全部保留。

```text
auto-trading-node --config <配置> job pull-plan
auto-trading-node --config <配置> recover
auto-trading-node --config <配置> status engine
auto-trading-node --config <配置> authorize confirm-recovery
auto-trading-node --config <配置> authorize arm --directions BUY --max-buy-value 1020 --max-order-value 1005 --max-positions 3
auto-trading-node --config <配置> halt
```

recover返回的是请求已接受；以status中对应状态版本完成核对为准，再确认恢复。急停以状态实际变为halted为准。
收盘模拟时刻15:30启动后执行job daily-export；seal-day返回前日封存引用，供次日EXIT配置绑定。EXIT授权使用SELL方向、买入额度0及明确单笔卖出上限。

```text
auto-trading-node --config <配置> job daily-export
auto-trading-node --config <配置> seal-day
auto-trading-node --config <配置> job retry
auto-trading-node --config <配置> status agent
auto-trading-node --config <配置> stop agent
auto-trading-node --config <配置> stop engine
```

任务计划依旧通过task-plan生成、install-node-tasks.ps1显式部署；本轮在实际任务入口运行job命令，系统已注册任务保持原状。
