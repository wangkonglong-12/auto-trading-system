# Mock Broker异常矩阵验收

## 1. 验收目标

TST-004把`MockBrokerGateway`的异常能力固定为一套可独立重复执行的验收矩阵。矩阵使用
注入时钟、内存券商事实和显式场景队列，在开发机与CI中得到相同结果。

## 2. 场景矩阵

| 能力 | 输入场景 | 必须成立的事实 |
|---|---|---|
| 受理 | `ACCEPT` | 返回单调请求序号，产生一条可查询的`ACKED`券商事实 |
| 拒单 | `REJECT` | 产生带原因的`REJECTED`终态事实 |
| 部分成交 | `PARTIAL_FILL` | ACK、部分成交更新和成交事实完整，累计量与剩余量一致 |
| 撤单 | `APPLY`、`REJECT` | 未成交与部成订单进入对应撤单状态；拒绝保留原订单事实 |
| 超时 | 提交/撤单的应用前与应用后超时 | 明确区分已知未应用和结果未知；结果未知可查询且同标识重报被阻断 |
| 重复 | `DUPLICATE` | 回调逐字重复，券商订单和成交事实仍各只有一份 |
| 乱序 | `REVERSED` | 成交可先于订单更新到达，最终可查询券商事实保持一致 |

专项目录`tests/integration/test_mock_broker_anomaly_matrix.py`逐项验证上表；底层参数、生命周期、
非法部分成交、查询故障和停止/恢复边界继续由`tests/unit/test_mock_broker.py`覆盖。订单意图门
与SQLite组合测试同时证明结果未知场景按`client_order_id`恢复，持久化失败时券商调用次数为零。

## 3. 执行方式

```powershell
.\scripts\verify-mock-broker-matrix.ps1
```

脚本固定运行四个测试文件，并在全部通过后输出包含七类场景的JSON结论。任何pytest失败均以
非零退出码终止，不输出成功结论。

## 4. 边界

本矩阵验收生产`BrokerGateway`端口的确定性测试替身及现有订单意图持久化门。QMT状态映射、
内部订单状态机和真实券商回调恢复由`QMT-005`、`ORD-001`至`ORD-003`在目标QMT环境继续验收。
