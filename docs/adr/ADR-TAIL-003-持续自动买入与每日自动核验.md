# ADR-TAIL-003 持续自动买入与每日自动核验

状态：源码实现及定向验证完成，默认关闭；现场重启、本人开启及真实成交验收待用户执行。

## 用户流程

用户保存交易设置后，预览每日数量、每日/单股/单笔金额和仓位上限，并本人确认一次“开启持续自动买入”。程序保持运行时，后续交易日自动等待正式优名单、查询账户、核对本系统委托和持仓、记录新恢复确认及当日BUY授权。日常页面不再要求用户到设置页手动核验或每天反复确认15分钟授权。

## 执行边界

- 持久化的是签名的操作员持续同意，绑定节点、账户、部署范围和完整设置摘要；它不是恢复旧进程的LIVE会话。每个新进程都要重新核验并形成新的Journal授权记录。
- 默认关闭；只支持显式TAIL_CLOSE单接口、三批优模式、BUY方向、卖出留空。代理、普通GET、浏览器传入金额和旧进程授权不能开启持续模式。
- 每次同意和撤销保存独立不可变证据；自动授权编号携带对应证据摘要。新会话限于当天正式计划的有效期和已安装本机额度，既有每日成交/未决预占不会因重新授权重置。
- 每日14:40—14:55才可新增买入，保留计划要求的撤单时段，14:56以后停止本轮交易授权。授权时长由当天计划决定，持续开关不受手工15分钟表单限制，也不会产生跨日的单个LIVE会话。
- 用户主动停止会撤销持续同意；修改设置也会关闭并要求重新确认。交易/Journal/QMT异常不自动重试授权，保留暂停原因；不能通过持续开关跳过系统未决委托。
- 资金仍以QMT真实可用资金为准。尾盘只数和持仓名额仅统计本系统记录；原有非系统持仓不被接管。已明确的零成交外部终态委托可以排除出系统恢复归属检查，未知或本系统委托不能排除。
- 收盘后自动核对并封存本系统持仓，供下一交易日使用。保留上一期引用以支持当天封存后的正常重启。程序需运行至完成收盘封存；未完成封存的异常关闭，或交易日历不覆盖买入日至下一交易日，均暂停并提示。
- 桌面每次启动（包括跨日切换）通过QMT适配器显式请求上一年1月1日至当年12月31日的SH/SZ交易日历，要求两市场一致、日期有序唯一且不丢失已安装交易日，原子缓存到账户私有目录，并让全部子进程加载同一份执行日历。异常返回不覆盖有效旧缓存；旧缓存不足则禁止买入。不猜测次年节假日，因此年末没有已核验下一交易日时仍需补足日历。QMT证券状态或行情不合格仍阻止买入，持续开关不能强行绕过。

## 验证范围

定向覆盖默认关闭、签名/配置防篡改、跨进程同意、账户隔离、自动核验及持久化控制、仅BUY、额度及三批去重、跨日封存、人工停止不重开、设置变更、超时及异常暂停、页面一次确认。测试只使用Mock券商，不发真实证券委托；不跑全仓检查。

本轮后台相关174项测试通过，后续修改又通过新模式/接口及无名单日收盘的定向复测；最后停止线程修正后的新模式、授权及日历24项测试通过，页面最终41项测试通过。8个相关源文件的定向类型检查、最终停止相关3源文件类型复测、页面定向类型检查、改动文件静态检查和最终前端构建通过。`node_app.py`整文件类型检查另发现原有`SystemSettings.quant_scheme`与`urlsplit.scheme`类型提示（系统设置路径，未在本轮改动），不视为全仓类型检查通过。前端仅从源码构建，不手工编辑生成文件。

复核修正了空请求被错误拒绝、持续预览编号被旧确认模型拒绝、开启响应迟到覆盖停止反馈，以及依赖过期状态缓存撤销授权的问题；设置保存改为向owner查询再关闭持续同意。独立紧急控制线程只立即暂停并设置线程安全停止标志，持续状态及文件仍由owner修改；旧开启预览无法清除后来的停止。其余未发现需阻止交付的本轮代码问题。既有`IsTrading=false`证券状态兼容问题未解决，不能据此宣称真实买入已验收。现场持续同意文件检查不存在，本轮未激活。

## 使用步骤

1. 用户自行关闭主程序并重新打开一次，加载这次后端与页面。
2. 在“交易设置”核对已保存并加载的额度；当前目标为每日新买1只、每日/单股/单笔各10000元、尾盘持仓1只、账户仓位100%，卖出留空。本轮未替用户修改现场设置。
3. 点击“开启持续自动买入”，预览真实额度并输入显示的确认文字。本人确认后，后续正常交易日不再手动核验或每天启动。
4. MiniQMT保持登录，主程序运行到收盘封存完成。关闭持续模式或出现安全异常后，需处理原因再本人重新开启；不会自行解除。

本轮不安装系统开机启动/计划任务，不替用户重启或激活现场程序，不改变凭据、不部署量化后台，也不执行实盘报撤单。
