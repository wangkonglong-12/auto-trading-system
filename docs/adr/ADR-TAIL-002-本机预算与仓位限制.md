# ADR-TAIL-002：本机独立预算与账户仓位上限

日期：2026-10-23。状态：源码实现；现场实盘准入独立验收。

交易设置页新增独立每日买入预算（新建默认600000元）和账户总仓位上限（默认70%，取值0.01–100%，最多两位小数）。现有预算不因升级自动覆盖；旧设置缺少仓位字段时加载70%。每日数量和单股金额不再相乘生成预算。

EngineKernel使用本机设置生成的EngineLimits，单股金额同时受本机与计划两者较小值约束。账户仓位限制按总资产乘百分比减证券市值、全部未成交买单及未观测本机预占计算；包含手工持仓/买单，观测到的部分成交已在证券市值中，只额外计未成交部分。本机已观测预占与券商订单合并计一次，未核清预占保守保留。

额度用于目标计算、J1前及J1完成后的SDK发送前复核；发送前复核排除当前候选自身的预占。账户观测不新鲜、不一致、总资产/市值缺失或总资产为零时无新增买入额度。超限不生成自动卖出；撤单沿用既有核验路径。LIVE缺少安装的仓位上限时拒绝买入。PAPER旧测试配置未指定仓位上限时保持原兼容语义。

既有撤单等待、重报次数（子单数=重报次数+1）、追价、价差、行情有效期和单笔股数由QmtTradingRuntime生成EntryPolicy；每日数量、总预算、单股金额、持仓数量、亏损停止线由本机引擎限制。恢复出的批次执行策略必须与当前安装的撤单、重报、追价、价差、行情时效及股数参数一致；不一致则拒绝恢复，避免新设置名义生效却继续使用旧策略。设置保存不直接扩大运行权限；完整配置指纹不匹配时禁止启用，重启仍暂停并要求本机授权。当前卖出规则为空，仍不构造自动卖出执行器。

定向验收覆盖前端默认值/独立保存/数值范围、后端版本化持久化、J1前及SDK前拦截、账户数据缺失、手工及部分成交委托、未观测预占、单股计划越界、三批额度/去重及既有执行策略。不运行全仓发布门，不以Mock验收代替真实报撤单许可。
