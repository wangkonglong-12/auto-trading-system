# 三批优信号与本机买入边界

日期：2026-10-23。状态：源码已实现；现场实盘准入另行验收。

## 已确认需求

后台14:40、14:45、14:50已完成定时结果中评级为优的股票到达即进入买入检查。同一账户同一交易日同一股票仅一个买入目标。三批共用本机每日股票数量及单股金额上限，未决委托占名额。卖出配置可以为空，为空时不建立退出执行器。页面只呈现真实QMT账户事实，未知不展示为零。

## 决策

保留唯一引擎所有者、账户互斥、独立SDK工作线程、Journal先持久化后提交、账户核验与本机人工授权。新增显式选择的三批模式；既有单份冻结计划继续走原路径。

每批为独立签名、不可变计划，最多三个。签名来源明确包含时点及优评级规则版本。后续批次必须使用相同账户、交易日、节点代际、策略、证券规则、执行窗口、风险预算和方向授权；同批不同正文、越界配置或签名失败均拒绝。接受新批次不增加本机权限。新批次不会替换旧批次的委托、买入目标或恢复证据。

三批计划中的目标金额表示候选证券上限，不要求所有候选都成交；本机依据实际成交和未决委托限制总金额与股票名额，持久化目标负责单股去重及补单数量上限。旧计划的分配总额约束保持原语义。

买入目标保留首次批次绑定，跨批去重采用账户、交易日、证券的持久化索引。重报只补原目标剩余数量。券商结果未知时保持占用，确认零成交且无在途委托后才能释放名额。

只读展示是独立查询投影，不向恢复核验或下单授权提供许可。手工成交不计入策略执行统计。成交均价按实际成交金额/数量计算，部分成交独立列出。

## 验证

覆盖三批重复证券、并发名额竞争、部分成交、撤单未知、重启恢复、同批正文冲突、配置/授权扩大、签名错误、卖出为空、手工成交隔离及真实QMT只读查询。完成改造后执行scripts/check.ps1全项目门。线上后台部署、任务注册、凭据与真实报单均不由本决策授权。

## 配置与迁移

本机设置保存`buy.signal_mode=TAIL_EXCELLENT_3_PHASES`、`buy.max_daily_symbols=N`、单股金额上限，日金额上限由N乘单股金额计算；`sell=null`、`emergency_liquidation_enabled=false`。高级账户总持仓上限独立保存，包含手工持仓；原持仓可能使可新增数量少于N，页面不将其算成本策略已买入。保存不修改正在运行的配置，必须停止并重启加载。不要在有未决旧计划的盘中切换模式，旧Journal、计划引用和持仓归属需先核验；本轮未修改真实设置。

量化账户批准配置或定期模板需要显式`selection_mode=TAIL_EXCELLENT_3_PHASES`；原默认值仍使用单份1440路径。现有量化数据将1440标为official、1445及1450标为experiment；新版仅在上述显式模式下使用这些时点已完成的scheduled快照，不修改原选股任务、评级或原结果角色。拒绝manual_force、缺失来源、失败或非完整结果，评级输入随来源冻结并签名。评级规则与既有`frontend/src/utils/tailHotDisplay.ts`保持一致。

后台可按时间顺序发布三份计划；当前查询响应附带较早批次，节点断线后逐份验签补接。已发布较晚批次后不插入新的早批次，避免倒退来源。后台数据库部署、已有发布任务的实际触发时间及选股完成后下一次触发延迟仍需现场核验。本轮没有注册或修改任何计划任务。

撤回会停止新增委托并持久化暂停状态，保留原批次用于恢复归属；重启或旧批次重放都不能重新激活。后续合法新批次也不会恢复已撤销的交易授权。单股去重记录不因确认零成交而删除，同日后批不再次建立目标；同一原目标允许在核验撤单后按设置补剩余量。

QMT行情需连续的60秒成交量窗口与可核验证券规则；缺失或异常时等待/停止，不能保证信号到达即成交。Windows报价接收和有效期校验使用同一高精度单调时钟，整元价格以普通小数字符串传递。真实交易时段仍需单独验收。
