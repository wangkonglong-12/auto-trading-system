# 尾盘选股单接口协议 V1

日期：2026-10-23。用途：量化后台与Windows自动交易系统共同开发、联调和验收。

状态：2026-10-23名单查询API及历史测试功能已部署，独立快照表已创建，专用只读令牌已配置。正式发布器、提交后钩子与5秒补偿任务尚未在线启用，本机QMT未切换。现有公网HTTPS证书过期；本轮通过SSH加密通道验收实际API，未放宽HTTP限制。本协议替代本次讨论中先前给出的三接口签名交易计划方案；现有V2签名计划路径保留兼容，通过本机tail_picks配置显式选择新接入。V1范围为同一套尾盘策略、同一套选股结果，不按QMT账户区分名单。

量化后台提供14:40、14:45、14:50定时选股中评级为“优”的候选；本机使用自己的QMT账户、交易设置和授权决定是否买入。后台不接收QMT账户、资金、密码、买入金额或买入数量，也不计算下单股数。

## 1 接口和传输

仅新增一个业务接口：

```http
GET /api/auto-trading/tail-picks?trade_date=2026-10-23
Authorization: Bearer <专用访问令牌>
Accept: application/json
```

| 项目 | 固定要求 |
|---|---|
| 方法、路径 | GET，`/api/auto-trading/tail-picks` |
| 查询参数 | 必填`trade_date`，严格`YYYY-MM-DD`；可选`test=true`或`test=false`，默认false。两个参数均不得重复，不接受其他参数 |
| 日期范围 | 服务器北京时间当天；本版不提供历史查询。非当天返回422，不回退到今天或最近有数据的日期 |
| 非交易日 | 当天非交易日返回422 `NON_TRADING_DAY`，交易日判断沿用量化系统交易日历 |
| 请求正文 | 无，非空正文或未知查询参数返回400 |
| 传输 | HTTPS并校验证书；本机不跟随重定向 |
| 认证 | 专用Bearer令牌；不用网页登录Cookie、登录密码或QMT凭据 |
| 响应 | UTF-8 JSON，`Content-Type: application/json`，不加`data`或`success`包装 |
| 缓存 | 所有响应`Cache-Control: no-store`，本版不用ETag/304 |
| 大小 | 响应正文最多65536字节；本机按解压后的正文限制大小 |
| 普通响应 | HTTP 200总是包含三个批次；不用204表示未完成 |

后台使用独立配置`AUTO_TRADE_TAIL_PICKS_ENABLED`（默认false）和`AUTO_TRADE_TAIL_PICKS_TOKEN`。令牌至少由32个随机字节生成，采用不带填充的base64url文本（43～256个字母、数字、下划线或连字符）；缺失或格式错误则接口不可用，不能回退成无认证。部署时由用户配置，不在源码或协议中放真实令牌。本机在Windows凭据存储保存它，通过本机配置引用；它与操作台登录密码无关。

令牌只授予读取这套名单的能力，不绑定或授予QMT账户交易权限。接口不需要account_id、node_id、payload、envelope、计划公钥或回执接口。

## 3 字段约束

所有表中字段都必填，包括值为null的字段。V1拒绝未知字段、重复JSON键、错误类型、NaN或Infinity；不能把字符串数字自动转换成整数。新增字段或改变语义时，两边同时升级协议版本。

| 顶层字段 | 类型 | 约束 |
|---|---|---|
| schema_version | 整数 | 必须为1；`"1"`、`true`不合法 |
| trade_date | 字符串 | 有效日历日期，严格YYYY-MM-DD，等于请求日期 |
| server_time | 字符串 | 本次形成响应时的服务器时间，必须为`YYYY-MM-DDTHH:mm:ss+08:00`，等于请求交易日；不返回缓存生成时间 |
| batches | 数组 | 长度恰好3，按1440、1445、1450排列，不能缺批或重复 |

| 批次字段 | 类型 | 约束 |
|---|---|---|
| phase | 字符串 | 只能为1440、1445、1450，保留前述固定顺序 |
| status | 字符串 | 只能为PENDING、READY、FAILED |
| source_run_id | 字符串或null | 量化原选股运行的稳定标识，1～96字符，仅字母、数字、下划线、点、冒号、连字符；READY必须非空，其他状态可null；没有时不能编造 |
| completed_at | 字符串或null | 原选股任务实际结束时间，格式同server_time；PENDING为null，FAILED可null；READY必须有值且同交易日、不得早于该批计划时点或晚于server_time |
| error_code | 字符串或null | PENDING/READY必须null；FAILED必须为第4节列出的错误码 |
| stocks | 数组 | 0～15只；PENDING/FAILED必须[]，READY允许[] |

| 股票字段 | 类型 | 约束 |
|---|---|---|
| code | 字符串 | 六位代码加大写市场后缀，如000001.SZ、600000.SH；V1仅支持SZ/SH；不能用裸代码、sh600000或交易所小写后缀 |
| name | 字符串或null | 真实名称，非空时去首尾空白、最多64字符；名称缺失用null，本机从QMT补取，不编造名称；不参与去重 |
| rank | 整数 | 每批重新连续编号1～K，按rank升序返回；K为本批股票数，不能重复或缺号 |

code完整正则为`^[0-9]{6}\.(SZ|SH)$`。同批code唯一；不同批次允许重复。超过15只时整批FAILED `TOO_MANY_STOCKS`，不能静默截断。如果业务需要更多，应先共同升级容量并验收。所有完整结构约束见随附JSON Schema；日期关系、连续rank、交易日、跨请求冻结等语义仍须执行本协议校验。

## 4 三个批次状态

| 状态 | 准确含义 | stocks与错误码 | 本机处理 |
|---|---|---|---|
| PENDING | 尚未到时点、任务未开始或仍计算中 | stocks=[]，error_code=null | 等下一次轮询，不当作选股为空 |
| READY | 本批成功、数据完整、来源和评级核验通过，已持久化冻结 | stocks可为空，error_code=null | 本地登记本批；候选进入买入检查，不等于立即下单 |
| FAILED | 本批当前无法提供有效结果 | stocks=[]，error_code非空 | 该批不新增买入；不阻塞其他READY批次 |

FAILED批次错误码：

| error_code | 含义 |
|---|---|
| SOURCE_FAILED | 该批定时选股任务明确失败 |
| SOURCE_INCOMPLETE | 数据健康非full、明细与头部数量不一致等完整性失败 |
| SOURCE_INVALID | 来源、日期、时点、证券代码、评级输入或排序等无法按本协议核验 |
| TOO_MANY_STOCKS | 筛选出的优候选超过15只 |
| SOURCE_NOT_READY_BY_CUTOFF | 当天14:55:00仍没有可发布结果；本接口本日不再补发布该批 |

READY之前允许PENDING/FAILED转为READY，前提是在14:55:00之前首次成功冻结。到达截止仍无结果的批次保持FAILED，不自动进入下一日，也不在截止后改为READY。

READY是本日该批的终态。之后不得修改source_run_id、completed_at、stocks、rank、name或状态，不得从READY退回PENDING/FAILED。同日同phase就是固定批次身份，无须额外batch_id。

如果发现已经发布的READY结果损坏或存在错误，整条接口返回503 `FEED_SUSPENDED`。禁止偷偷换名单、删除股票或以空列表覆盖。客户端暂停新增自动买单并保留原委托和记录，需人工处理后才能恢复交易授权。

## 5 后台来源和优评级

读取当前尾盘选股的定时任务结果，不修改选股算法、原调度时点、原角色或原结果。1440读取official，1445/1450读取experiment；均要求run_mode=scheduled，拒绝manual_force。源交易日与请求一致，源planned_decision_at为当日对应14:40:00、14:45:00、14:50:00。

对同日同phase，以**第一个符合全部条件并被成功冻结的定时运行**作为唯一来源。没有合格结果时可继续等待该时点的定时重试；不得以昨天、其他时点、人工重跑或任意旧成功记录替代。冻结后新增运行不替换本批。

发布条件是源任务status=succeeded、data_health=full、完成事务已提交，且头部pick_count与本次读取到的完整明细数一致。数据覆盖数量仅作现有完整性判断，不增加本协议之外的隐含评分阈值。读取头部和明细应处于同一个一致性事务。

优评级固定使用TAIL_EXCELLENT_V1，与现有`frontend/src/utils/tailHotDisplay.ts`的非legacy“优”展示一致：

1. 先计算本批是否存在正式入选的normal/primary主召，排除补充观察股票。
2. 单只必须有合法entry_tier、market_bucket、有限score_total和非null尾盘价格close。tier取股票字段，缺失时取source_meta.entry_tier，并去空白转小写。
3. 正式入选指selected不为false、supplemental不为真且display_role不为score_band_observation。缺失标志只能按既有页面兼容规则解释，不能在数据适配时丢掉已有false/观察标记。
4. normal或primary正式入选：纳入。
5. fallback正式入选：仅20cm_cyb或20cm_kcb、60≤score_total<70且本批存在前述主召时纳入。10cm fallback不纳入。
6. 其余不纳入。字段缺失按页面规则判为风险，不把风险股票当优。

候选按原rank_no升序、code升序确定顺序，再连续编号1～K。同一来源存在重复code属于SOURCE_INVALID，不自行合并。只返回优股票，不按本机配置的最多买入数量裁剪；不同批次重复证券照常返回。

优评级输入和筛选规则版本保留在后台冻结证据中，供排查；不要求把所有评分字段传到本机。对照的是该冻结来源的页面评级，之后页面切换到人工重跑或新运行不回写本批。

## 6 后台持久化与发布

在自动交易模块拥有的独立MySQL表保存冻结批次，例如`auto_trade_tail_pick_batches_v1`，以(trade_date, phase)为唯一约束。保存READY批次完整内容、原来源标识、TAIL_EXCELLENT_V1规则版本及内部摘要。名称也在冻结内容中。

选股完成事务提交后，发布器读取并筛选，原子写入一个完整READY批次；写入成功后查询才能返回READY。并发或重复发布命中唯一约束时读取已保存内容，不能覆盖。源原始数据后来被改动时不重建同批结果，冻结副本继续保留原内容；冻结副本的正文、摘要或状态不一致时暂停接口。

GET仅查询冻结记录和轻量任务状态，不触发选股、补数、评级重算、数据库迁移或发布写入。三个批次应在一次一致性读取中形成响应，不在一次响应中混用不同查询时刻的批次状态。

采用事务提交后触发发布，加5秒一次的模块补偿检查；补偿仅扫描当天三个时点的完成状态和缺失冻结记录，不重跑选股，不扫描历史大表。后台自己收齐三个冻结批次后也停止读取当天原选股数据，后台重启先检查MySQL冻结记录。要求源成功提交后正常情况下5秒内能读到READY，实际延迟在现场联调中测量。

发布器须在有更晚READY批次时继续处理尚未READY的早批，不得因1450已完成就永久跳过迟到的1440。不同批次互不等待，整体受14:55:00发布截止约束。

跨日读取只返回当天数据，不能用昨天的记录填充。部署、迁移、定时任务启用、访问令牌配置另行执行，本协议文件不代表已经执行这些操作。

## 7 HTTP异常

HTTP非200统一返回下列结构，不附batches。反向代理等返回HTML或不符合结构时，客户端一律按请求失败处理。

```json
{
  "schema_version": 1,
  "error": {
    "code": "SERVICE_UNAVAILABLE",
    "message": "选股结果暂时无法读取，请稍后重试。",
    "retryable": true
  }
}
```

| HTTP | error.code | retryable | 客户端行为 |
|---|---|---|---|
| 400 | INVALID_REQUEST | false | 参数、格式、重复/未知参数或正文错误，停止请求并提示修正 |
| 401 | UNAUTHORIZED | false | 令牌缺失或无效，停止请求并提示配置；返回WWW-Authenticate: Bearer |
| 403 | FORBIDDEN | false | 凭证没有读取权限，停止请求并提示 |
| 422 | UNSUPPORTED_TRADE_DATE | false | 非服务器北京时间当天，不回退日期 |
| 422 | NON_TRADING_DAY | false | 非交易日，本日不再轮询 |
| 429 | RATE_LIMITED | true | 按Retry-After等待，不并发或密集重试 |
| 503 | SERVICE_UNAVAILABLE | true | 数据库/服务暂不可用，保留本地记录并退避重试 |
| 503 | FEED_DISABLED | false | 功能开关关闭或服务端缺少令牌配置，提示待启用 |
| 503 | FEED_SUSPENDED | false | 已发布结果冲突/损坏，暂停新增买单并提示人工处理 |

429和可重试503必须带`Retry-After`，值为1～60的整数秒。服务异常不返回200加空名单。正常业务FAILED批次用200表达，数据库无法可靠读出三个状态时用503，二者不得混淆。

鉴权失败不泄露令牌是否存在、数据库细节或账号信息。意外500由客户端按临时故障处理，不采信其正文作为候选。

## 8 本机轮询与校验

本节是显式启用新单接口后的行为；未配置新接入时仍采用原每分钟签名计划链路。

1. 交易日14:39:50开始，每5秒查询一次当天结果，14:55:00停止发起新查询。程序在此窗口内启动时立即发起第一次查询。使用后台北京时间交易日历及本机交易日配置核对日期。
2. 请求连接超时3秒、完整请求截止8秒；最多一个在途请求。未完成不重叠发请求。一次完成后至少间隔5秒再查询。
3. 网络错误及可重试503按5、10、20、30秒退避；收到有效200后恢复5秒。429/503有合法Retry-After时按该值等待（1～60秒）；缺失或非法按退避处理。非重试错误停止自动重试并提示。
4. 验证HTTPS、令牌用途、HTTP状态、正文大小、JSON Schema及第3节语义；server_time与本机当前北京时间偏差超过30秒、源时间越界、日期不匹配均拒绝，不自动改系统时间。
5. 以(trade_date, phase)持久化已接收READY批次。重复结果内容一致就复用；只比较批次冻结内容，不把每次变化的server_time当作新批次。引擎本地上下文与原始日名单均保存成功才确认接收；保存失败不会确认当天收齐，并立即阻断新增发单。原有已持久化目标仍保留供恢复核验。
6. 三个批次全部READY（包括READY+[]）并成功落盘后，当天立即停止HTTP请求。程序或agent重启后先查引擎恢复出的完成状态，不再次请求量化接口。FAILED不算收齐；未收齐继续查询，直到14:55:00停止。下一交易日重新开始。收到最终响应但确认回包丢失时，先向本机引擎核对完成状态，不能直接重拉。
7. 在仍轮询期间，已见过的READY消失、退回非READY或内容变化，视为冲突，暂停新增买单，保留原记录，需人工核验。本机不自动接受“新版同批名单”。收齐停止后不再查询远端变化；READY不可变是本协议前提，紧急停止仍使用本机操作通道。
8. 收到多个新READY批次时按1440、1445、1450处理，同批按rank处理。未完成早批不阻塞晚批；早批迟到时仅检查剩余名额，不抢占已建立目标，也不重排在途委托。
9. 尚未收齐时，最近一次完整校验通过的200响应距今超过15秒，名单连接视为失新，暂停新增买单，保留委托核验与风险处理。三批收齐后使用冻结本地结果，不再要求网络保鲜。普通短暂网络故障后可在有效响应恢复且原本机授权仍有效时继续；冲突/FEED_SUSPENDED导致的暂停需人工核验，不自动恢复授权。
10. 接口结果从不授予交易权限。本机仍需已启用自动买入、账户核验通过、行情有效、未超过本机新增买入截止时间、资金及风险限制允许。本版本机停止新增时间为14:55:00、撤单窗口截止14:56:00，本次本机授权可更早截止。在新增截止之后收到的名单仅保存，不补买。
11. 新协议接入使用独立适配路径。引擎将通过认证与校验的名单转换成自己账户下的本地执行上下文，以自己的私有安装密钥签名以便恢复；它不是后台签名计划，后台不需要签名或预算字段。保留本机单一引擎、Journal先持久化、逐股日内去重、在途预占、金额与名额上限、QMT权限和恢复保护。

本机以(QMT账户, 交易日, code)做有效买入目标去重。不同批次出现相同code不建立第二份目标；部分成交及在途委托占用名额和额度。撤单结果未知不释放占用；补单只能补原目标剩余量。股票名称不参与去重。卖出规则仍为空。

无需接收回执或成交回传接口即可完成本版取名单与买入。将来若需后台看成交，作为另一项功能另定协议，不改变本接口的选股职责。

## 9 历史只读测试

在同一接口加`test=true`：

```http
GET /api/auto-trading/tail-picks?trade_date=2026-10-23&test=true
Authorization: Bearer <专用访问令牌>
```

`trade_date`仍必须为查询当天，北京时间；测试可在非交易日或非尾盘时段发起。不传`test`或传`test=false`严格沿用当天正式查询，绝不回退历史。

测试服务在包含当天的366个自然日范围内，按日期倒序查找最近一个至少有一只合格“优”股票的日期。仅复用原定时成功且数据完整的来源、固定时点和相同优筛选规则，跳过正常空结果、没有优股票的日期及不合格来源。允许一天只有部分批次可用，其他批次真实保留PENDING或FAILED；不强求三批都有股票，不跨日期拼批，不接受人工重跑，不执行历史选股，不写冻结表。查询本身有数据库及服务时间预算，超时返回可重试503，不能伪装NOT_FOUND。

测试响应使用独立结构，以下字段均必填：

| 字段 | 语义 |
|---|---|
| schema_version | 整数1 |
| mode | 固定TEST；正式名单解析器不接受此结构 |
| status | FOUND或NOT_FOUND |
| requested_date | 查询当天，严格YYYY-MM-DD |
| trade_date | FOUND为真实选股日期；NOT_FOUND为null |
| server_time | 当前真实北京时间，whole-second +08:00，不改成历史日期 |
| lookback_days | 固定整数366，包含当天及之前365天 |
| batches | FOUND恰好三批且按1440/1445/1450排列，至少一批READY且有股票；NOT_FOUND为[] |

批次字段复用第3节，completed_at保留真实历史完成日期。NOT_FOUND明确表示本窗口内没有合格优股票，不表示选股任务正常完成。Schema和真实联调样例见`v1.test-response.schema.json`及`v1.test-response.example.json`。

本机诊断入口`python -m auto_trading_system.sync.tail_feed_probe`只做获取、结构/日期/批次校验和跨批证券去重统计，生成`executable=false`报告；不连接QMT，不写Journal、引擎完成状态或执行上下文。线上获取使用`--origin <HTTPS源地址> --output <新报告路径>`，令牌从环境变量`TAIL_PICKS_TEST_TOKEN`读取；也可用`--input <刚取得的测试响应>`检查。输入仍校验服务器时钟，离线旧制品不冒充当前有效响应。正式引擎拒收TEST结构，即使历史日期碰巧等于当天也不例外。

新增令牌只用于本接口，不替换浏览器登录密码、Cookie、JWT密钥或QMT凭据。当前HTTP源`http://8.210.85.242:8001`上的直接请求会返回400，不应将专用令牌放在明文公网请求中。本轮实测采用SSH加密通道到运行中的8001服务，以受信任回环代理信息验证HTTPS路径；这不代表公网HTTPS证书已修复。

## 10 联调验收清单

两端使用同一JSON Schema、示例和下列用例验收，不只检查接口返回200。

| 编号 | 场景 | 预期 |
|---|---|---|
| 01 | 三批都未完成 | 三个PENDING，均空名单，不能下单 |
| 02 | 1440完成、有优股票 | 返回真实来源与有序候选，本机登记一次 |
| 03 | 1445正常完成、无优股票 | READY+[]，区别于PENDING |
| 04 | 选股失败、partial、来源缺失 | 相应FAILED，不伪装空成功，不回退旧日数据 |
| 05 | 主召、20cm fallback、10cm fallback及补充观察 | 与现有页面优评级逐例一致，覆盖60/70边界及无主召 |
| 06 | 连续请求同一READY | 内容不变，只有server_time可变化，本机不重复建目标 |
| 07 | 三批重复同一股票 | 后台允许返回，本机同日同账户一个有效目标 |
| 08 | 名额N与单股金额上限 | 后台不裁剪，本机成交和在途共用限制 |
| 09 | 重复code、rank缺号、证券后缀错误 | 整批或整响应校验失败，不部分采信 |
| 10 | 超过15只优股票 | FAILED TOO_MANY_STOCKS，无静默截断 |
| 11 | 同时发布、重复发布、后台重启 | MySQL冻结记录复用，不生成不同同批结果 |
| 12 | 本机断线、三批收齐后继续运行或重启 | 当天不再有选股HTTP请求；先查本机恢复状态，保留日内目标，不重复买；重启仍需本机核验与授权 |
| 13 | 早批迟到、晚批先完成 | 晚批不阻塞，迟到批仅使用剩余额度，不抢占 |
| 14 | READY内容变化、消失或状态倒退 | 本机暂停新增买单；后台冲突返回FEED_SUSPENDED |
| 15 | 到14:55仍未完成、截止后才完成 | 保持SOURCE_NOT_READY_BY_CUTOFF，不自动补发布/补买 |
| 16 | 跨日、非交易日、请求历史日期 | 不使用昨天数据，按HTTP错误约定处理 |
| 17 | 令牌缺失、错误、功能关闭、限流 | 按401/503/429结构处理，无认证绕过 |
| 18 | 超时、HTML错误、数据库故障、返回超大正文 | 不采信为候选，不重叠请求，失新后不新增买单 |
| 19 | schema版本/类型/时区/完成时间错误 | 严格拒绝，无静默类型转换 |
| 20 | 选股事务完成到API可见的延迟 | 记录实际时间，正常情况下≤5秒；本机首次请求再测总延迟 |

现有本机行情执行还有60秒成交量窗口等条件。API可见延迟和实际成交延迟须分别验收，不能将“收到READY”写成“已经买入”。
