日期：2026-10-23。源码版本：`0.1.0.dev56`，未变更既有发行EXE。

当前补充：名单API及`test=true`历史只读查询已在用户授权后部署，真实服务和本机解析验收通过；正式发布器未上线，本机QMT未切换。当前状态与最新2640/203项验证见[历史测试部署验收](尾盘选股历史测试部署验收_20261023.md)。下文“未部署、未迁移、默认关闭”等为本轮首次本地开发完成时的记录，已由此补充更新；原始测试数量保留作历史证据。

## 实现范围

两个项目已实现单接口V1的源码。量化端按原定时运行的优评级冻结名单，本机接收名单后，以本机账户、设置和授权执行；HTTP查询没有账户字段、后台预算、签名计划或接收回执。默认开关保持关闭，正在运行的真实QMT只读节点没有更改。

用户补充的停止规则落实为：三批全部READY，包括正常空批，经引擎成功保存原始日名单和本地执行上下文后，当天停止选股HTTP请求。agent重启或程序重启先查引擎恢复的完成状态，不再请求后台。最后一批保存成功但回包丢失时，下次也先查本机确认状态。PENDING和FAILED不能冒充收齐，继续查询到14:55；网络临时故障退避重试。格式冲突、不可重试接口错误或保存故障阻断新增买单，不能以失败确认收齐。

## 量化端代码

路径相对于`E:/workspace/ai-stock-assistant/backend/`：

| 文件 | 职责 |
|---|---|
| app/api/auto_trading/tail_picks.py | HTTPS、Bearer、单日单参数校验、读接口、错误格式、并发和频率上限 |
| app/protocol/auto_trading/tail_picks.py | 严格V1模型；与本机模型共享同一源码内容 |
| app/repositories/auto_trading/tail_picks_repository.py | 一致性读取原选股头部和明细、优筛选、MySQL不可变批次与摘要核验 |
| app/services/auto_trading/tail_picks_feed.py | 三批状态查询、发布截止和收齐后不再读取源数据 |
| app/services/tail_hot_picks_service.py | 完成事务提交后的默认关闭通知钩子；不更改选股算法 |
| app/core/auto_trading/scheduler.py | 默认关闭的5秒补偿任务；复用既有单进程调度器 |
| scripts/auto_trading/migrations/20261023_tail_picks_feed_v1.sql | 独立快照表DDL，显式执行，不在服务启动时迁移 |
| tests/auto_trading/test_tail_picks_feed.py | 来源、评级、HTTP、冻结、截止、停止和跨项目贯通检查 |

只有`AUTO_TRADE_TAIL_PICKS_ENABLED=true`时才运行发布器；只启用此开关不要求开启旧V2发布器或配置后台账户批准预算。必须配置独立`AUTO_TRADE_TAIL_PICKS_TOKEN`，采用至少32随机字节生成的base64url文本。本文不提供真实令牌。

表名为`auto_trade_tail_pick_batches_v1`，不修改原选股表。READY正文、SHA-256和状态须一致；后续请求只读冻结副本。名单收齐后发布器只做内存日期检查，后台重启先读MySQL冻结记录，不重取原选股数据。

## 本机代码与运行方式

| 文件 | 职责 |
|---|---|
| protocol/tail_picks包 | V1结构、日期/时区、批次状态、连续rank和证券去重校验 |
| sync/tail_feed.py | HTTPS客户端、8秒截止/3秒连接超时、5秒间隔、失败退避、完成后停止 |
| sync/node_agent.py | agent单工作线程串行轮询，不重叠；新模式不调用旧计划/日终上传接口 |
| runtime/tail_feed.py | 引擎再次校验、持久化日名单、本地执行上下文、恢复和完成状态 |
| runtime/node_engine.py | 认证本机管道交接、配置模式隔离和错误停止 |
| config/node_v2.py | 显式新模式和独立令牌引用；没有该项则行为保持旧模式 |

本机仍使用既有受保护节点目录与Journal。停止并核验旧委托，保留原买入归属、授权与恢复记录后，在日终窗口安排切换；不能以新建空库的方式绕过当天去重。新接入要求安装三批买入设置、`sell=null`，QMT档位为显式`QMT_TRADING`；配置本身不启动自动交易，每次重启仍须核验与人工授权。

本机配置增加下列字段，值仅为引用示意，不是可直接启用的完整生产配置：

```json
{
  "tail_picks": {
    "token": {
      "source": "WINDOWS_CREDENTIAL_MANAGER",
      "target": "AutoTrading/<本机节点标识>/tail-picks-token"
    }
  }
}
```

后台源地址仍使用`quant_origin`，可使用`quant_ca_file`指定私有CA，同时校验证书和主机名。旧配置模型中的`quant_key_id/quant_secret/trusted_plan_keys`为兼容字段，在新模式的选股路径不使用，不需要向后台提供旧账户或签名计划配置，也不需要为此新建旧HTTP凭据。原模式保持原同步行为。

引擎内部的本地执行上下文使用`critical/tail-feed-local-key.bin`私有安装密钥，后台没有此密钥。本地来源时间以真实任务完成时间及本机首次接收时间为界，不将接收时间倒填成选股时点。它只保存执行/恢复证据，不产生交易授权。持久化还包括`tail-feed-state.json`及独立`tail-feed-phase-plans.json`；备份和恢复必须保留它们和原Journal，密钥丢失或已保存内容不一致会阻断恢复。

备份明确允许上述三个文件，并保留原三批上下文、每日风险基线和开盘参考。已增加创建备份、核验清单、逐字节恢复及恢复后仍需核验的完整往返测试。同日已保存的冲突暂停状态跨重启保留；当前未提供一键清除该状态的界面，须人工核验和维护，普通恢复按钮不清除来源冲突。

尚未收齐时，15秒没有有效名单响应就阻止新增买单；收齐停止后不以网络不更新判为失新。实际QMT报价、账户观测、原授权、金额和数量限制始终有效。本机新增买入截止14:55，撤单窗口截止14:56，实际授权可更早结束。名单到达不等于报单，更不等于成交；60秒成交量窗口等原执行条件保留。
