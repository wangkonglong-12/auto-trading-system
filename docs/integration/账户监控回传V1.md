# 账户监控回传 V1

当前状态：2026-11-03 源码开发及隔离验证阶段。未部署、未执行真实 MySQL 迁移、未保存真实上传凭据、未重启现场程序或回传真实账户数据。本阶段没有页面和用户读取接口。

## 数据与边界

- Windows 节点通过已有 QMT 会话和 SDK 工作线程读取完整资金、持仓、当日逐笔成交，支持 QMT_TRADING 和 QMT_READ_ONLY。不会通过交易归属过滤手工成交，不使用截取前 100 条的展示结果。
- 独立 agent 工作线程启动后立即尝试，每 60 秒再次尝试；无需登录本机网页、准备策略、启动买卖或执行任务按钮。失败后自动重试，没有需要手工解除的暂停锁存。
- 生产首次接入需一次性部署、配置账户绑定和独立令牌。随后普通退出、重启、断网恢复均自动接续，不需要重新开启功能。不注册额外系统计划任务。
- 本地独立 `jobs/.account-reporting.sqlite3` 保存最新快照、持久序号及成交待传队列，不打开交易 Journal。最多 50,000 笔未确认成交；达到上限保留原队列并报告 PENDING，不静默丢弃。后台确认的成交在本地保留 7 天供当日重复查询去重；未确认成交不按日期清理。
- 本地 `jobs/.account-observation.json` 是原子替换的单份完整采集交接文件；不会逐分钟新增快照文件。资金采集、持仓采集和本次采集完成均保留时间，窗口大于 5 秒拒绝发布。跨查询并非券商原子快照，不宣称交易账务一致性。
- 当前接口只能查询当日成交。程序跨日未运行期间的交易不保证能补齐，已有持仓的原始买入日期也不据此伪造。`trade_history_scope=CURRENT_DAY_ONLY` 明确来源范围；不从持仓减少编造卖出。此阶段不计算持仓周期、收益或成本归属。

## 三表

迁移文件在量化项目 `backend/scripts/auto_trading/migrations/20261103_account_monitoring.sql`，须显式执行；应用启动不执行 DDL。

| 表 | 主键 | 内容 |
| --- | --- | --- |
| account_assets | account_id | 每账户最新资金、来源节点、快照序号及摘要、采集及接收时间、成交来源范围 |
| account_positions | account_id + symbol | 当前持仓数量、可卖量、冻结量、市值、采集时间 |
| account_trades | account_id + trade_date + market + trade_id | 逐笔真实成交方向、数量、价格、券商成交金额、成交及首次接收时间、内容摘要 |

每个账户只有一个绑定写入节点。资金和完整持仓在一个事务内替换；有效空仓会清除当前持仓，缺失字段、查询失败、账户错配或截断数据不会进入此事务。较旧序号不覆盖当前资金/持仓，但仍可补交未传成交。相同序号不同正文或相同成交身份不同内容返回冲突，不覆盖历史。同一事务中成交写入失败会回滚资金和持仓。

持仓行表示股票当前余额，不代表一轮持仓周期。清仓后当前行消失，成交历史保留；再次买入形成新成交，当前持仓恢复，前次历史不改写。第一版只传有可靠来源的字段；股票名称、成本价、现价及浮盈暂不扩展。

## 接口

`POST /api/auto-trading/account-snapshots`，HTTPS 且校验证书，不跟随重定向。

请求头：`Authorization: Bearer <独立账户监控令牌>`、`Content-Type: application/json`。

请求模型以两项目同内容的 `protocol/account_monitoring.py` 为准：

- `schema_version=1`、`node_id`、`account_id`。
- `snapshot.sequence`：本机持久递增序号。
- `snapshot.observation`：资金和持仓采集时间、完成时间、资金对象、完整持仓数组、空的 trades 数组、成交来源范围。
- `trades`：最多 1,000 笔尚未确认的成交，可以包含先前交易日已经采集并留存的成交。成交时间按北京时间确定交易日，身份再包含市场及券商原始成交编号。
- 金额使用十进制文本，数量使用整数。载荷最大 8 MiB，完整持仓最大 10,000 项；超限拒绝，不能截断后上传。

回执含 `schema_version=1`、`batch_hash`、`received_at`。仅接受与本次完整请求摘要一致的回执后，才将相应成交标记为已确认。回执丢失后重传不重复插入。每分钟最多请求一次，超出一批的成交后续分钟继续发送。

后台状态：200 已提交或幂等重传；400 请求不完整/未来时间/非 HTTPS；401 无效凭据；403 节点或账户越权；409 源身份、序号或成交内容冲突；503 未启用、繁忙或暂时不可用。节点均保留待传成交并在后续周期重试，状态只输出固定原因，不记录账号密码、令牌或原始异常。

所有数据库时间为 UTC DATETIME(6)，JSON 时间必须带时区。未来页面展示采集及接收时间，不增加“数据可能已过期”的提示。

## 一次性接入配置（本轮不操作真实环境）

节点配置新增：

```json
{
  "account_reporting": {
    "token": {
      "source": "WINDOWS_CREDENTIAL_MANAGER",
      "target": "<受保护凭据引用>"
    }
  }
}
```

复用既有 `quant_origin` 和可选 `quant_ca_file`，账户监控要求 HTTPS。令牌为独立随机的 43—256 位 base64url 文本，与现有 IPC、签名、选股、统一接口及交易上报令牌分离。

量化后台配置：

```text
AUTO_TRADE_ACCOUNT_REPORTING_ENABLED=true
AUTO_TRADE_ACCOUNT_UPLOAD_GRANTS=[{"node_id":"<节点别名>","account_id":"<账户别名>","token":"<独立监控令牌>"}]
```

未配置时默认关闭，不能因为升级代码便上传真实账户。令牌绑定由服务端核对，不能由客户端自行切换账户。没有新增公网读取接口；后台登录用户的查看范围随页面阶段设计。
