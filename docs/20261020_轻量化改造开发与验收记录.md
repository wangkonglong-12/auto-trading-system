# 个人轻量化自动交易系统：本轮开发与验收记录

> 更新于 2026-10-21：本文最初记录的是分阶段开发状态。下方内容已同步为当前代码现状，避免把已经完成的事项继续显示成“未开发”。真实券商小额委托验收仍需在交易日由账户持有人明确执行。

日期：2026-10-20。范围以用户确认的尾盘策略边界为准：选股由现有量化后台完成，本机在 14:30–14:55 拉取当日入选计划并负责行情订阅和交易执行；卖出采用每笔买入成本价上的止盈、止损和最晚卖出规则。

## 已完成

1. 本机操作台改为首页、卖出规则、规则测试、交易、消息与记录五个日常入口；原有进程与恢复控制收在设置。首页保留暂停自动交易的醒目操作，并明确显示模拟或真实只读环境及数据更新时间。
2. 三项卖出参数有独立校验：止盈和止损按各持仓批次成本价计算，最晚时间只允许在留有申报余量的交易时段内；午休不可设为截止时间。规则测试用输入的成本、当前价格和北京时间显示触发原因，明确标注未发出委托。
3. 操作员可保存规则草稿，版本递增；并发旧版本保存、存储损坏和写入失败返回明确错误。草稿不自动激活、不产生交易权限。
4. 签名退出上下文可携带 `COST_EXIT_V1` 冻结规则；策略持仓退出 owner 在有效行情、可卖数量、券商账户和挂单约束下计算单一目标。委托记录保留正确规则版本；重复行情不会产生第二笔子单。
5. 保留旧 `T1_EXIT_BASELINE_V3` 研发模拟的兼容性；正式启动档使用独立 `QMT_TRADING`，只读检查继续使用 `QMT_READ_ONLY`，页面会明确区分，不会把模拟或只读环境显示为实盘交易环境。
6. 新增独立QMT单笔调试链路：使用已经验证的230825b SDK执行异步报单、一次撤单、回调采集和委托查询核对；账户、资金/可卖数量、重复备注及审批nonce均在发单前复核。系统本地订单号由QMT短备注确定生成，重启后仍可关联；外部手工单保持未归属，不会冒充系统订单。即使异步报单回调丢失，也会使用本次唯一备注从券商委托查询中恢复关联；查询到多个同备注订单时停止并要求人工核对，不会重发。
7. 新增QMT交易事实Gateway，将当日委托、成交、资金和持仓转换为系统统一模型；当前先供隔离测试与后续主流程接线使用。新增运行脚本固定使用QMT专用Python与SDK，不再误用普通测试环境。调试结果不可覆盖写入，未知结果不重发。
8. 补齐卖出规则的模拟启用入口：规则页会核对草稿内容与引擎已安装的`COST_EXIT_V1`模拟退出会话，只有完全一致才显示可启用；启用时方向、总额、单笔金额和持仓数上限全部由后端受信配置生成，浏览器不能提交或放大额度。确认授权后页面显示正在模拟运行的规则版本；急停或未授权时回到未运行状态。实际子进程验收使用成本价止盈规则完成买入、跨日恢复、卖出和重启不重卖。
9. 交易页接入系统订单撤单：后端只把本系统拥有、已取得券商委托号且尚未终态的订单标为可撤；外部手工委托只展示。页面采用两次点击确认，撤单请求仍需经过操作员会话、CSRF、当前授权、订单归属、原委托绑定、关键日志落盘和SDK单线程派发；返回“已请求”后继续以券商查询结果为准。
10. 新增独立 `QMT_TRADING` 长驻调试档并接入真实交易 Gateway。它与 `QMT_READ_ONLY` 分开校验，必须配置本机操作员口令；启动时仍为零自动额度和暂停状态。新增 `run-qmt-node-debug.ps1` 固定使用已验证的QMT Python/SDK，页面会明确显示“QMT 实盘调试”，可查看真实持仓、委托、成交及恢复状态，不会误显示为模拟盘，也不会出现模拟授权按钮。
11. “消息与记录”同步展示最近委托和成交；交易页展示资金、总资产、持仓可卖数量、逐笔委托、逐笔成交及订单归属。自动退出 owner 已有超时撤单、部分成交核对、等待原单终态后按剩余数量重新报价的闭环；重复行情和结果不明不会重复下单，停止新增委托和最终撤单截止时间由冻结退出会话约束。
12. 纠正选股来源和计划窗口：选股由用户现有量化后台完成，本机不重复实现选股算法；交易日 14:30–14:55:59 每分钟检查当日计划，发现有效入选结果后立即加载，不等到窗口结束。任务计划、运行时双重时间校验、页面文案和当前方案文档已统一。
13. 完成选股清单驱动的 QMT 行情订阅和实盘买入执行：`QMT_TRADING` 加载计划后按排名提取股票代码并调用 `subscribe_quote`；同一计划重复加载不会重复订阅，计划换股会同步增删订阅，计划撤回或进程退出会退订。SDK 回调只做有界校验和入队，主线程使用最新盘口、QMT 涨跌停价和最小价格单位生成保护限价委托。字段异常、合约详情缺失、订阅失败或队列溢出都会暂停交易。超时委托先撤单，只有券商终态、成交和账户重新核对完成后，才按新行情重报剩余数量。
14. 新增单页“交易设置”：买入区只保留当日、单只、单笔金额上限及未成交等待、重新下单次数；卖出区配置按持仓买入成本计算的止盈、止损和最晚卖出时间；安全区配置当日最大亏损、最多持仓数和紧急清仓开关。固定使用最新卖一价保护限价方式，技术参数默认收在“高级设置”中。设置按版本原子保存，并发旧版本、金额层级错误、只填写部分买入额度以及缺失硬风控都会被拒绝；保存仍只产生草稿，不会自动取得实盘权限。没有保存过交易设置时，页面和后端同时锁定启动与恢复授权，系统只允许查看、配置和急停；已有持仓不会套用默认卖出规则。
15. 本轮复核修复六处交易边界：买单到达等待时间后即撤单，不再依赖价格先发生变化；60 秒成交量使用逐标的滚动窗口计算，并在时间或累计量回退时重置；价格保留 QMT 返回的实际精度，支持 0.001 元最小价位；退订及停止后清理旧行情缓存；紧急清仓立即撤销本系统未完成订单并等待券商终态；买卖执行均读取 QMT 行情交易状态，只有连续竞价状态才允许生成新委托。
16. 修正首次启动流程：缺少实盘配置时不再阻止系统启动，而是进入完整的未连接操作台；页面明确显示“尚未连接 QMT”，订阅、下单和清仓全部锁定。“系统设置”提供“开始连接 QMT”入口并自动识别 SDK 路径，配置保存后自动切换到正式节点；非敏感路径保存在本机，原环境变量方式继续兼容。

## 仍需现场完成的启用事项

- 正式量化后台地址、节点账户绑定、HMAC 凭据、计划签名公钥、策略版本和交易日历需要写入正式 `QMT_TRADING` 节点配置，并与量化后台登记一致；仓库中的旧调试配置不能代替正式配置。
- 页面保存设置后，实盘节点需要重启才能装载新的硬限制。每次启动仍保持暂停，必须由本机操作员登录、完成账户恢复核对并确认本次实盘授权。
- 本轮没有发送真实证券委托或撤单。代码闭环和冻结程序已验收；券商是否已经为该账户实际开通函数交易权限，只能通过交易时段内经账户持有人明确授权的小额真实报单、撤单和回报核对确认。
