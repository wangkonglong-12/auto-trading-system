# 个人尾盘自动交易系统：简洁版方案与执行计划

日期：2026-10-20。依据用户提供的豆包 A+B+C 方案及本次确认：选股由用户现有的量化后台完成；交易系统在交易日 14:30–14:55 调用计划接口发现当日入选股票，随后订阅这些股票的行情并执行受控买入。止盈、止损和到时卖出作为本机可配置的卖出规则。以后增加其他策略时再扩展。

## 目标

用户每天打开一个程序，就能看清账户、量化后台是否发布当日入选股票、卖出规则、正在处理的订单和需要自己处理的问题。操作顺序是“设置卖出规则 → 测试规则 → 模拟运行 → 实盘运行 → 查看结果”。页面讲人话；计划拉取、交易恢复、同步与对账等工程细节留在后台。

## 每天怎样用

1. 登录后进入首页。顶部固定显示模拟盘或实盘、账户、连接状态和数据更新时间。
2. 在“策略与卖出规则”设置三个必需项：相对这笔持仓的买入成本价涨到多少卖、跌到多少卖、最晚几点卖。页面同时说明它们针对哪些持仓。
3. 在“规则测试”输入或选择历史场景，看三种触发条件各会在何时要求卖出。完整收益回测使用量化后台的历史入选结果与对应规则版本；结果注明数据缺口。
4. 先在模拟盘启动，观察“产生信号 → 风控检查 → 发出委托 → 券商接受或拒绝 → 成交或撤单”。模拟结果符合预期后，再进入实盘启用流程。
5. 运行期间通常只看首页。异常出现时点“查看原因”；需要停止时点醒目的“暂停自动交易”。
6. 在“交易”查看持仓、可卖数量、挂单和成交。可以撤可撤委托；紧急卖出另设按钮，先预览再确认。

## 页面：五个日常入口

| 入口 | 直接显示 | 操作 |
| --- | --- | --- |
| 首页 | 环境、账户与连接、资金、持仓、买入策略是否已接入、卖出规则是否运行、待处理订单、最新异常及更新时间 | 启动/暂停；异常直达原因 |
| 策略与卖出规则 | 展示量化后台当日选股计划的接收状态；“自动卖出”明确设置止盈比例、止损比例、最晚卖出时间和适用持仓 | 修改卖出规则、保存、参数检查、去规则测试 |
| 规则测试/回测 | 先展示卖出规则在历史或模拟行情下的触发时间、拟卖数量、未成交原因；买入策略接入后再展示完整收益曲线和逐笔回测 | 运行测试、查看触发过程、返回同一规则版本 |
| 交易 | 持仓和可卖数量、未完成委托、部分成交、当日成交及券商原因 | 撤单、受保护的紧急卖出 |
| 消息与记录 | 按时间排列信号、风控、发单、券商回复、成交和异常 | 按日期/股票筛选；查看失败原因 |

首页从上到下只放四块：①“现在能否运行”的一句话状态和暂停按钮；②资金与持仓摘要；③买入策略与自动卖出规则的当前状态；④最近五条交易或异常消息。图表和技术监控不挤占首页。规则页按“填三个条件→保存→测试→启用”的顺序摆放按钮；参数错误直接指出具体字段。测试完成后保留结果，返回规则页仍是刚才的版本，不要求重新填表。

所有页面都有空数据、连接中断和数据过期三种清楚的提示。颜色之外还用文字说明状态；重要错误不因刷新或点“清空消息”而消失。技术日志藏在单条记录的“详细信息”里，日常页面不展示内部编号和状态机名称。

登录页和账户、风险设置放在右上角“设置”，不占日常主导航。首期只有一个 MiniQMT 股票账户；选股规则继续由现有量化后台管理，本机不重复实现选股编辑器，不做账户列表、策略列表、新建/复制策略、Python 在线编辑器、任意指标拼装及多角色后台。豆包的十页功能没有消失：信号与日志进入“消息与记录”，账户配置进入“设置”，规则设置与测试仍有清楚的独立入口。

页面用词固定：显示“暂停自动交易”，不显示 HALT；显示“券商尚未确认”，不显示 UNKNOWN；显示“数据已过期”，不只给错误码。失败时说明下一步，例如检查 MiniQMT 登录状态或等待券商订单核对。

## 量化后台选股与本机买卖执行分开

选股由现有量化后台运行。本机在交易日 14:30–14:55 轮询当日计划接口；尚无结果时继续等待，发现经过签名和账户、日期、版本、预算校验的入选股票后立即加载计划，订阅相应股票行情，并在计划允许的买入时间和价格范围内执行买入。重复返回同一计划不会重复下单；结果撤回或发生新版变更时先暂停并核对已有委托。卖出规则作用于这些买入成交后形成的持仓批次。

自动卖出页面只需要三个主要输入：

| 用户看到的设置 | 系统动作 |
| --- | --- |
| 涨到多少卖：止盈比例，例如填写 X% | 达到指定涨幅时，将本策略可卖持仓的目标收紧到零并申请卖出 |
| 跌到多少必须卖：止损比例，例如填写 Y% | 达到指定跌幅时立即申请卖出，并持续跟踪委托与成交；无法成交时醒目告警 |
| 最晚几点卖：交易日时间 HH:MM | 到时仍有本策略可卖持仓，就申请卖出剩余部分，并跟踪是否真正成交 |

用户已确认：止盈、止损均以本策略这笔持仓经成交核实的买入成本价为基准，涨跌幅＝（最新有效价格－该笔买入成本价）÷该笔买入成本价。多笔买入分别按各自持仓批次判断，不使用前一日收盘价或账户里其他股票的平均成本。成本价缺失、无法对应本策略持仓或与券商事实不一致时，不猜测触发价，页面告警并等待核对。三项条件都以券商确认的持仓、可卖数量和最新有效行情为前提。普通股票当日新买入的数量通常尚不可卖；“最晚几点卖”应用在该批持仓首次可卖的交易日，之后仍未成交的剩余数量继续列为待处理。时间选择要限制在实际可申报且留有处理余量的窗口内。若同一时刻多个条件成立，只形成同一个“卖出剩余持仓”目标，不重复发单；已有卖出挂单先核对，必要时受控撤改单。触发“必须卖”表示系统必须尝试并持续跟踪，无法保证券商实际成交。收盘仍未卖出的数量不标记“已清仓”。

保存规则会产生新版本，页面展示生效时间。修改运行中规则时先暂停、核对已有委托，再启用新版本；重启后不能自动恢复旧授权。规则测试、模拟与实盘共用同一版本。完整收益回测要等买入策略定稿并接入后才能计算，不能用现有模拟买入假装完成。

## 模拟、实盘与安全

- 模拟和实盘使用不同账户绑定、配置及数据目录。页面切换只能选择已安装的环境，不能把模拟订单切到真实通道。实盘有醒目标识，启动前展示账户、规则版本、资金与风险上限并再次确认。
- “暂停自动交易”禁止新的自动报单，同时显示已有挂单及撤单入口。重新运行前先核对账户与订单。
- “紧急卖出”是独立、受保护的操作，只处理当前可卖数量；先预览，再确认，逐笔显示受理、拒绝、成交或待核对，不承诺一次点击全部成交。
- 仓位和单日亏损上限由后端在发单前检查。亏损基准或账户数据不能确认时停止新开仓并显示原因；已确认的卖出规则保留独立运行权限及安全限制。
- 信号不等于订单。MiniQMT 返回的异步请求序号也不等于成交；结果未知时先查询券商事实，禁止盲目重发。
- 页面只负责展示、保存设置和请求受保护操作。行情判断、风控及报撤单由交易引擎执行。

## 豆包 A+B+C 怎样落地

| 内容 | 采用方式 |
| --- | --- |
| A：登录→首页→策略→回测→启动→看信号/订单/日志 | 保留完整操作顺序；买入股票来自量化后台在 14:30–14:55 发布的当日计划 |
| A：普通人可配置策略 | 首先提供止盈、止损和最晚卖出时间三个直接可懂的设置 |
| A：信号监控 | 完整保留，在消息与记录里按一条交易过程显示，首页和交易页可直接进入 |
| B：十张 MySQL 表 | 用来检查需保存哪些事实，不直接执行 SQL；先映射现有本地 SQLite 和量化 MySQL，缺少的信号事实再做最小增量 |
| C：独立引擎、安全控制、模拟/实盘隔离 | 全部作为必须实现和验收的后台能力 |

MiniQMT 实际通过 XtQuant、本机 userdata_mini、会话号及券商账户连接；不照搬豆包文档中适用于通用云 API 的 API Key/Secret/Endpoint 配置。

## 执行顺序

| 阶段 | 工作 | 可验收结果 |
| --- | --- | --- |
| 1. 改页面和用词 | 将旧十个占位入口及当前现场台整理为五个日常入口；首页先接已有模拟状态 | 不看技术文档也能找到策略、回测、订单、暂停及失败原因 |
| 2. 自动卖出规则 | 实现止盈%、止损%、最晚卖出时间三个配置项及计算基准；同一目标去重、持仓/可卖/挂单核对、版本保存和规则测试 | 三种条件分别触发一次；重复行情和重启不重复发单；未成交有明确告警 |
| 3. 模拟完整流程 | 把现有模拟持仓、卖出、撤单、恢复和风险限制接入页面；补齐信号及原因记录 | 从卖出触发到委托与成交可追踪；暂停、风险触发、撤单和重启状态一致 |
| 4. 真实账户只读 | 复用当前源码的 QMT_READ_ONLY 档位，验收交易时段行情、资金、持仓、委托、成交与断线；接入同一界面 | 页面事实可与 MiniQMT 核对，标明更新时间；只读档位始终不能报撤单 |
| 5. QMT 实盘报撤单开发与调试 | 在独立实盘档实现异步报单、撤单、回报、订单关联、未知结果查询及恢复；先用模拟 SDK 验证，再用绑定账户和受控单笔范围进行现场调试 | 每笔真实委托、成交和异常可核对，遇到未知结果停止重发并提示核查 |
| 6. 量化后台选股与完整上线 | 将量化后台当日计划、行情订阅、受控买入和现有卖出设置做现场串联，完成联合回测、模拟和小额度实盘验收 | 从发现当日入选股票到首次可卖日的止盈、止损、到时卖出均可追踪且可复核 |

量化后台负责选股，本机负责 14:30–14:55 发现计划、订阅行情、风控和交易执行。阶段 2 的涨跌计算基准已确认采用这笔持仓的买入成本价；具体止盈%、止损%和最晚卖出时间由用户在页面填写。现场验证所需交易日单独排期。

用户补充明确：`QMT_READ_ONLY` 只是核对账户与券商事实的调试档，不能作为最终实盘能力的替代。开发范围包含独立实盘档的报单、撤单和回报链路；现有只读档继续用于连接与数据核对。两档应在配置、数据目录、界面标识及授权上区分，不能通过前端切换把只读会话升级成交易会话。QMT 异步返回的请求序号仅表示请求发出，实盘可用须由委托、成交、拒单、撤单和断线后的核对共同验证。

## 当前基础

现有 dev54 桌面 EXE 默认 Mock、零额度、只读；已有本地登录、急停、模拟授权和模拟订单/恢复核心。旧十路由大多是占位；量化系统已有计划和每日历史记录。当前退出规则代码含固定测试阈值，它们只是研发基线，尚不是这三个用户可配置项。当前源码已有 QMT_READ_ONLY 长会话档位，可读取真实账户事实，但真实报撤单被明确禁止，现有发行 EXE 也不应标为实盘可用。
